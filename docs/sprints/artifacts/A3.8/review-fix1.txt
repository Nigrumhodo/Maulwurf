This review closes the three hoplite findings on `a9b4316`:

1. **Whitespace-only values passed the CHECKs.** "Blank" now means
   `btrim(value, E' \t\n\r\f\v') = ''` (plain `btrim(value)` only strips spaces, so a tab
   would still pass). Two `IMMUTABLE` helpers are created by `0013`:
   `public.maulwurf_text_is_blank(text)` and
   `public.maulwurf_text_array_has_blank(text[])` (a CHECK cannot contain `unnest()`).
   The write calendar, both settings arrays and `calendar_id`, `event_id`, `remote_status`
   and `etag` all use them. `parse_remote_event` now trims the ETag and stores a blank one
   as NULL; it also trims the remote status (blank -> `confirmed`) and rejects a
   whitespace-only event id with `event_id_invalid` before the DB is touched.
   Regression cases cover `""`, `"   "`, `"\t"` and `" \t "` for every field; the array
   cases also mix a valid calendar with a blank one.
2. **`0013` did not normalize every field its CHECKs cover.** The migration now uses the
   same helper in the cleanup: a whitespace-only ETag becomes NULL, a whitespace-only write
   calendar becomes NULL, and NULL/empty/whitespace-only array elements are removed. An
   incomplete coverage window is still reset to "never synced"; a complete window keeps its
   timestamps after the array cleanup. A blank `calendar_id`, `event_id` or `remote_status`
   cannot be normalized without inventing a remote identity, so the migration rejects those
   rows with a `RAISE EXCEPTION` naming the per-field counts (and a hint), instead of
   failing later on an opaque `ADD CONSTRAINT`. Both paths are covered: the round-trip test
   seeds whitespace-only values and asserts the normalized result, and the rejection test
   asserts the message, the rollback to `0012` and that `FORCE ROW LEVEL SECURITY` is still
   enabled on both tables.
3. **`try/finally` could mask the original error.** It is gone. PostgreSQL DDL is
   transactional: a failure rolls back the whole revision, including the temporary
   `NO FORCE ROW LEVEL SECURITY`, so the `finally` would only have run inside the aborted
   transaction and raised `InFailedSqlTransaction`. The rejection test above exercises that
   failure path and confirms RLS is restored.

The array-element criterion is validated against the real database by
`tests/integration/test_calendar_settings_mirror.py` (head schema) and the migration tests;
the helper functions are created and dropped by the round-trip test.
