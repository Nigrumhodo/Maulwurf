# S4.2 Hoplite review fixes — 2026-10-31

Review: Hoplite over head `07494bf`, 2026-10-31T22:06:19Z. Verdict: no blockers for the
single-instance path; findings 1 and 2 to resolve before marking S4.2 done.

## Findings and code changes

1. Admission not synchronized across instances.
   - `supervisor.sweep_pass` now calls `admission.restore_from_database(pool)` before
     `sweep_once` on every periodic pass; `run_sweeper` calls `sweep_pass`.
   - `docs/ESPECIFICACION.md` (F1 ingestion) still describes a single ingestion instance;
     the per-pass read is kept because the durable row is authoritative and the extra
     query is one indexed lookup per 60 s pass.
   - Tests: `tests/test_sweeper.py::test_every_pass_resyncs_the_persisted_latch`,
     `test_sweep_pass_reads_the_latch_before_recovering`, and the integration case
     `tests/test_reception_latch.py::test_foreign_failed_cleanup_closes_admission_on_the_next_sweep_pass`.

2. A database outage closed admission with no reopen path.
   - `admission` now separates the durable latch (`_halted`, sticky, only a persisted
     `cleanup_status=failed` sets it) from the transient close (`_transient_closed`,
     set by a failed/unreadable read). A successful read with no `failed` row clears only
     the transient close; the durable latch stays closed. `halt` is idempotent per
     attempt so repeated reads do not duplicate alerts.
   - Tests: `test_a_clean_pass_reopens_a_transient_close`,
     `test_a_persisted_failed_latch_is_not_reopened_by_clean_passes`,
     `test_transient_close_reopens_after_a_readable_latch`,
     `test_durable_halt_survives_a_clean_latch_read`.

3. Recovery lease (30 s) vs heartbeat (10 s).
   - `SupervisorConfig` validates `3 * heartbeat_interval_s <= lease_ttl`; the defaults
     (10 s / 30 s) leave one missed beat plus the next one before expiry. An unsafe
     interval fails at construction.
   - Tests: `test_default_heartbeat_leaves_three_beats_before_lease_expiry`,
     `test_a_heartbeat_without_margin_is_rejected`.

4. `record_cleanup(verified=False)` left a previous `audio_deleted_at`.
   - `lease.record_cleanup` now sets `cleanup_verified_at` and `audio_deleted_at` to NULL
     on the `failed` transition (the `verified` transition still stamps them).
   - Test: `tests/test_cleanup_admission.py::test_failed_cleanup_clears_a_previous_audio_deleted_at`.
