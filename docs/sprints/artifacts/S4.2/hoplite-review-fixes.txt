# S4.2 Hoplite review fixes — 2026-10-31

## Findings and code changes

1. Admission not synchronized across instances.
   - `supervisor.sweep_pass` now calls `admission.restore_from_database(pool)` before
     `sweep_once` on every periodic pass; `run_sweeper` calls `sweep_pass`.
   - `docs/ESPECIFICACION.md` (F1 ingestion) still describes a single ingestion instance;
     the per-pass read is kept because the durable row is authoritative and the extra
     query is one indexed lookup per 60 s pass.
   - Tests: `tests/test_sweeper.py::test_every_pass_resyncs_the_persisted_latch`,
     `test_sweep_pass_reads_the_latch_before_recovering`, and the integration case
     `tests/test_reception_latch.py::test_foreign_failed_cleanup_closes_admission_on_the_next_sweep_pass`.

2. A database outage closed admission with no reopen path.
   - `admission` now separates the durable latch (`_halted`, sticky, only a persisted
     `cleanup_status=failed` sets it) from the transient close (`_transient_closed`,
     set by a failed/unreadable read). A successful read with no `failed` row clears only
     the transient close; the durable latch stays closed. `halt` is idempotent per
     attempt so repeated reads do not duplicate alerts.
   - Tests: `test_a_clean_pass_reopens_a_transient_close`,
     `test_a_persisted_failed_latch_is_not_reopened_by_clean_passes`,
     `test_transient_close_reopens_after_a_readable_latch`,
     `test_durable_halt_survives_a_clean_latch_read`.

3. Recovery lease (30 s) vs heartbeat (10 s).
   - `SupervisorConfig` validates `3 * heartbeat_interval_s <= lease_ttl`; the defaults
     (10 s / 30 s) leave one missed beat plus the next one before expiry. An unsafe
     interval fails at construction.
   - Tests: `test_default_heartbeat_leaves_three_beats_before_lease_expiry`,
     `test_a_heartbeat_without_margin_is_rejected`.

4. `record_cleanup(verified=False)` left a previous `audio_deleted_at`.
   - `lease.record_cleanup` now sets `cleanup_verified_at` and `audio_deleted_at` to NULL
     on the `failed` transition (the `verified` transition still stamps them).
   - Test: `tests/test_cleanup_admission.py::test_failed_cleanup_clears_a_previous_audio_deleted_at`.

## Fix2 review (head `4d93399`, 2026-10-31T22:25:41Z)

Findings left open by Hoplite and their corrections:

1. The sweeper did not start when the service pool failed at startup.
   - `main.start_sweeper` now always starts `main.run_sweeper_when_pool_ready`.
     The new loop retries `open_service_pool` every `INGEST_SWEEP_INTERVAL_S`
     until `app.state.pool` is a pool, then calls `run_sweeper`; a pool-open
     exception is logged by type and retried too. The startup pass may still close
     admission, but the first successful pass re-reads the latch and reopens the
     transient close.
   - Tests: `tests/test_sweeper.py::test_start_sweeper_retries_the_pool_until_it_opens`
     (unit) and `test_the_sweeper_starts_after_a_failed_pool_open_at_startup`
     (integration: the first open fails, the second sets the real pool, and a
     stranded attempt is ended by the real sweeper).

2. An unverified cleanup that could not persist `failed` (token moved by
   `sweep_stranded`/reclaim) only logged.
   - Chosen option: explicit alert + metric, not "pending + lost lease blocks
     admission". The row stays `pending` because there is no durable `failed` row
     to reopen admission from; `admission.flag_unrecorded_cleanup` appends
     `Alert("cleanup_unrecorded", attempt_id)`, logs
     `ingest.alert code=cleanup_unrecorded`, and the supervisor increments
     `maulwurf_ingest_failures_total{stage="cleanup",error_code="cleanup_unrecorded"}`.
     Admission stays open. The decision is documented in `docs/plan/S4.md` (S4.2)
     and `docs/RUNBOOK-dev.md` §8.
   - Tests: `tests/test_cleanup_admission.py::test_unrecorded_unverified_evidence_alerts_without_closing_admission`,
     `test_unrecorded_cleanup_exception_alerts_without_closing_admission` (unit) and
     `test_unrecorded_cleanup_on_a_moved_token_stays_pending_and_alerts`
     (integration: `sweep_stranded` moves the token, the old lease's unverified
     evidence writes no row, admission stays open and the alert is recorded).

3. A raising `leases.record_cleanup` inside the cleanup-error branch aborted the
   whole recovery pass, including `sweep_stranded`.
   - `reconciler._record_cleanup` wraps both evidence writes (the exception branch
     and the normal branch), logs `reconciler.cleanup_record_failed` with the
     exception type only and returns `None`; the pass continues with the next
     attempt. The docs only reach the log, never the DSN.
   - Tests: `tests/test_reconciler.py::test_a_raising_record_cleanup_does_not_skip_the_stranded_sweep`
     and `test_a_raising_record_after_verified_evidence_also_continues`
     (integration: the stranded attempt is still ended).

No `apps/web` change and no provider/Riva call.
