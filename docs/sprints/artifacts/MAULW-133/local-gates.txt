Environment note
----------------
The sandbox restarted into an image without PostgreSQL or Redis, so both were installed
locally for this capture. Other Maulwurf worktrees share the original :5432/:6379
services and run `alembic upgrade head` at the same time; those migrations execute
`ALTER ROLE "maulwurf_app" ...` and PostgreSQL can answer `tuple concurrently updated`,
failing a session-scoped migration fixture before any test runs. The final suite therefore
ran on an isolated cluster (:5434, UTF8) and an isolated Redis (:6381) to avoid measuring
another worktree's contention. A first attempt on the shared services also exposed a
distro pgvector 0.6 without `hnsw.iterative_scan`; pgvector 0.8.0 was built from the
v0.8.0 tag to match CI. No test or production code was changed to accommodate either
environment limitation.
