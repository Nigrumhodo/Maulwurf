S4.5 — peak-RSS portability validation (Hoplite review fix1), 2026-11-01T02:46:58Z
Host: Linux 7.0.0-39-generic x86_64 · Python 3.12.3 · ffmpeg 8.1.2 · espeak-ng 1.51

Problem: the S4.5 load case measured worker peak RSS only from VmHWM in
/proc/self/status. gVisor hides VmHWM, so the value was None and the test failed instead
of reporting RAM as NO VERIFICADO. Fix: process_hwm_bytes() falls back to
getrusage(RUSAGE_SELF).ru_maxrss (the same kernel peak, in KiB on Linux), and the load
case skips with an explicit reason when neither source exists.

Validation method: a test-only LD_PRELOAD shim, never committed, makes
/proc/self/status unreadable (open/open64/openat/fopen return ENOENT). With
MAULWURF_TEST_HIDE_MAXRSS=1 it also zeroes getrusage(RUSAGE_SELF).ru_maxrss. This
simulates the gVisor condition; it was not run on a real gVisor host.

    static int is_target(const char *path) {
        return path != NULL && strcmp(path, "/proc/self/status") == 0;
    }

    int open(const char *path, int flags, ...) {
        static int (*real)(const char *, int, ...) = NULL;
        if (!real) real = (int (*)(const char *, int, ...))dlsym(RTLD_NEXT, "open");
        if (is_target(path)) { errno = ENOENT; return -1; }
        mode_t mode = 0;
        if (flags & O_CREAT) {
            va_list ap; va_start(ap, flags); mode = va_arg(ap, mode_t); va_end(ap);
        }
        return real(path, flags, mode);
    }

    int open64(const char *path, int flags, ...) {

    int openat(int dirfd, const char *path, int flags, ...) {
        static int (*real)(int, const char *, int, ...) = NULL;
        if (!real) real = (int (*)(int, const char *, int, ...))dlsym(RTLD_NEXT, "openat");
        if (is_target(path)) { errno = ENOENT; return -1; }
        mode_t mode = 0;

    }

    FILE *fopen(const char *path, const char *mode) {
        static FILE *(*real)(const char *, const char *) = NULL;
        if (!real) real = (FILE *(*)(const char *, const char *))dlsym(RTLD_NEXT, "fopen");
        if (is_target(path)) { errno = ENOENT; return NULL; }
        return real(path, mode);
    }

    int getrusage(int who, struct rusage *usage) {
        static int (*real)(int, struct rusage *) = NULL;
        if (!real) real = (int (*)(int, struct rusage *))dlsym(RTLD_NEXT, "getrusage");
        if (who == RUSAGE_SELF && getenv("MAULWURF_TEST_HIDE_MAXRSS") != NULL) {
            memset(usage, 0, sizeof(*usage));
            return 0;
        }
        return real(who, usage);
    }

A zero `VmHWM` is also treated as missing and falls back to `ru_maxrss`; the unit case
`test_peak_rss_ignores_a_zero_vmhwm` pins it.

Conclusion: VmHWM remains the primary source; ru_maxrss is used only when VmHWM is
unavailable or zero, and the RAM term stays NO VERIFICADO with an explicit skip when
neither exists. The load case never fails because of a missing kernel field and never
publishes an invented zero. No repository file is written by the shim; it is
validation-only.
