== fix3 summary
1. [Media] Transient reconcile PATCH. `_reconcile` now catches
   GoogleCalendarTransientError around `gateway.update_event` and re-reads the event:
   it adopts the write (RECONCILED, ETag of the new state persisted) only when the
   event already carries the exact body this delivery sent; otherwise it leaves the
   event untouched, marks the task failed and returns EXTERNAL_CONFLICT. A lost
   response can no longer be retried against the old baseline and reported as a false
   external edit.
2. [Media] ETag of the reconciliation PATCH persists before the newer-version repair.
   `_repair_newer_version` writes the ETag of the PATCH that already landed on the
   newer row before any repair GET/PATCH (skipped only when another delivery recorded
   a different, therefore newer, baseline), and swallows transient repair read/write
   errors as deferred. A lost repair response is re-read and adopted only when the
   event carries the newest body. The next delivery no longer sees the ETag produced
   by our own write as an external edit.
3. [Riesgo de despliegue, sin cambios] No migration in this PR creates `tasks` or
   `tasks.calendar_etag`; A3.1 must add the nullable column before any producer is
