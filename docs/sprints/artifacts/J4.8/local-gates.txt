Review fix2 — hoplite finding 1 on head e9e0b1e (2026-11-01)
  Finding: migration 0019 created its five indexes with plain CREATE INDEX inside the
  Alembic transaction. That takes a SHARE lock on messages, transcripts, notifications,
  outbox_events and google_remote_operations for the whole build, blocking chat, ingest and
  outbox writes on a deployment with traffic.

  Change (TDD; the tests below failed first and pass on the fix):
    - 0019 upgrade/downgrade: op.get_context().autocommit_block() with
      postgresql_concurrently=True. Each index is dropped first with
      DROP INDEX CONCURRENTLY IF EXISTS, so the non-transactional build is retry-safe: a
      crash between indexes (or an invalid leftover) converges on the next upgrade instead of
      failing with "already exists".
    - alembic/env.py: the migration advisory lock is session-scoped and taken with
      pg_try_advisory_lock + short polls. Rationale: 0019's autocommit commit releases a
      transaction-scoped lock, and a *blocking* session lock deadlocks with CREATE INDEX
      CONCURRENTLY (which waits for every older snapshot).

  Red evidence, before the fix:
    $ uv run pytest tests/integration/test_migrations.py -q -k "budget_aggregate"
    2 failed, 1 passed
      test_budget_aggregate_indexes_are_built_concurrently:
        assert 'CREATE INDEX CONCURRENTLY messages_by_created_at' in
        "BEGIN; ... CREATE INDEX messages_by_created_at ON messages (created_at); ...
         COMMIT;"
      test_budget_aggregate_indexes_recover_from_a_partial_run:
        asyncpg.exceptions.DuplicateTableError: relation "messages_by_created_at"
        already exists

  Red evidence, migration change without the env.py change:
    $ uv run pytest tests/integration/test_migrations.py -q -k "concurrent_upgrades"
    1 failed  (3 runs, 3 failures)
      ERROR [alembic.util.messaging] Online migration expected to match one row when
      updating '0018' to '0019' in 'alembic_version'; 0 found
    (the transaction-scoped lock was released by 0019's commit; a second replica ran 0019)

  Red evidence, blocking session lock instead of polling:
    asyncpg.exceptions.DeadlockDetectedError: deadlock detected

              blocked by process B.

              blocked by process A.
    (CREATE INDEX CONCURRENTLY waits for B's snapshot while B waits for the lock)
