  The settings model treats empty as absent; startup does not mistake it for an invalid
  previous key.

Interpretation: `ingest` accepts a current plus optional previous key during a dual-key
rotation; with no previous pair the old key is rejected. Compose now passes
`INGEST_CREDENTIAL_PREVIOUS_SECRET`/`_KID` to `ingest` only (never to `api`), and the CI
allowlist includes them.

- `invalid_grant` disconnects the integration and is never retried.
- An old/wrong ingest `kid` is rejected; the previous pair is accepted only while it is
  configured.
- A missing NVIDIA key makes ASR unavailable instead of using a placeholder.
- Google access/refresh tokens remain encrypted; the schema has no plaintext token column.

Known limitation recorded by the runbook: `MAULWURF_ENCRYPTION_KEY_VERSION` has no
multi-version keyring or re-encryption job. Changing it in production would make stored
Google tokens unreadable; it is a stop condition, not a supported rotation.
