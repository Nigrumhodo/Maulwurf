Real Google reconnect (2026-11-16)
First attempts failed after a successful consent: the API log recorded
  GET https://www.googleapis.com/calendar/v3/users/me/calendarList -> 403 Forbidden
  calendar.connect_failed code=google_calendar_forbidden transient=False
while the callback already carried the three Calendar scopes. That is a project-level
403, not a consent or token problem: the Google Calendar API was not enabled for the
OAuth client's Cloud project.
After enabling the Google Calendar API in that project and retrying reconnect:
  GET https://www.googleapis.com/calendar/v3/users/me/calendarList -> 200 OK
  POST https://www.googleapis.com/calendar/v3/calendars -> 200 OK
and the database shows:
  google_credentials.status = connected, with calendar.calendarlist.readonly,
    calendar.app.created and calendar.events.readonly granted;
  settings.calendar_write_calendar_id set (remote ID redacted here), updated 18:24 UTC;
  therefore calendar_write_ready = true (connected + calendar id + scopes).
No code change was needed for the fix. The earlier 403 is kept here as the reason the first
two attempts failed and to document that the UI banner was honest, not a client bug.
