## 1. Ticket summary

- **Objective:** guarantee, through a documented decision and a test, that Redis contains
  **only IDs and state**, with no large payloads, audio, transcripts or tokens; durable
  persistence lives in Postgres.
- **Scope:** Redis ADR (`ADR-0005`), service configuration in compose, documented value
  size threshold and a sweep test with exercised flows.
- **Out of scope:** job reconstruction after losing Redis (J2.3), backoff/retries
  (J2.1), observability (J2.5), rate limits (S4).
- **Typed dependency:** `code` J1.1 (`redis` service); `contract` §1.3 (only IDs and
  non-sensitive configuration); `format` accepted ADR-0004
  ([../../adr/ADR-0004-commits-pr.md](../../adr/ADR-0004-commits-pr.md)) and the L1.2 ADR
  style in `docs/adr/`.
- **Deliverables:** `docs/adr/ADR-0005-redis.md`; `redis` block of the compose with the
  policy applied; `apps/api/tests/integration/test_redis_policy.py` (I-S1-JF-03).
- **Acceptance criteria:**
  - [ ] The ADR documents the decision, threshold, key/TTL catalog and the consequences
    of losing Redis.
  - [ ] The configuration applied in compose matches the ADR (persistence, `maxmemory`,
    policy).
  - [ ] I-S1-JF-03 green: no key exceeds the threshold after exercising the S1 flows.
  - [ ] No Redis volume or bind unless the ADR decides and justifies it.
- **Tests/evidence:** **I-S1-JF-03** with command, date, environment and result; without
  dumping key values to the logbook (only sizes/boolean patterns).
- **Planned files:** `docs/adr/ADR-0005-redis.md`,
  `apps/api/tests/integration/test_redis_policy.py`, `infra/docker-compose.yml`
  (`redis` section).

## 2. Delivery design

### 2.1 Proposed decision (to freeze in the ADR)

| Topic | Proposed decision | Reason |
|---|---|---|
| Source of truth | PostgreSQL/`outbox_events` | Redis can be lost and jobs are regenerated from the DB (J2.3) |
| Redis persistence | disabled: `--save "" --appendonly no` | avoids an unaudited durable copy; the outbox is already durable |
| Eviction | `--maxmemory-policy noeviction` | fail visibly rather than silently evicting jobs |
| `maxmemory` | `${REDIS_MAXMEMORY:-256mb}` (provisional) | bounds the container; reviewed in J2/S4 |
| Value threshold | **4 KiB per value** (documented) | IDs, states, counters and short ARQ results fit; nothing larger belongs in Redis |
| Key catalog | `arq:*` (ARQ internal), `arq:health-check:*`, `mw:*` IDs/state only | every new key is documented in the ADR |
| TTL | ARQ results `keep_result=60`s; health keys 30–60 s | no long-lived state |
| Forbidden | audio, transcripts, texts, prompts, tokens, credentials, PII | privacy rule (G1) |
| Exposure | no port published to the host; `data` network only | reduces the exposed surface |

> If the team decides on Redis persistence, the ADR must justify the case and still keep
> `FLUSHALL` as a loss recoverable from the outbox (I-S2-JF-03).

### 2.2 Configuration in compose

```yaml
  redis:
    image: redis:7.4-alpine@sha256:<digest>
    command:
      - redis-server
      - --save
      - ""
      - --appendonly
      - "no"
      - --maxmemory
      - ${REDIS_MAXMEMORY:-256mb}
      - --maxmemory-policy
      - noeviction
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 20
    networks: [data]
    restart: unless-stopped
```

- Without `volumes:` (ADR default). If one is added, it must be in the ADR and in the
  evidence.

### 2.3 Test I-S1-JF-03

`apps/api/tests/integration/test_redis_policy.py` (marker `integration`, docstring
"G1"):

1. **Exercise S1 flows:** `/readyz` (ping), worker/scheduler startup
   (`arq:health-check:*` keys), enqueueing and consuming the `index`/`analyze` stubs
   from the dispatcher once J1.5 exists.
2. **Sweep:**
   - `SCAN` all keys; for each one, size by type
     (`STRLEN`/`LLEN`/`HLEN`/`MEMORY USAGE`).
   - Assertion: `max(sizes) <= THRESHOLD` (read the threshold from the ADR; do not
     hardcode two values).
   - Shape assertion: allowed values (UUID, integer, short enum, JSON of IDs) via regex.
   - Negative assertion: no key contains audio/text/token markers (e.g. long base64,
     `Bearer `, `NVIDIA`, text with spaces > N).
3. **Configuration:**
   - `INFO persistence` → `aof_enabled:0`; `CONFIG GET save` empty (per the ADR).
   - `CONFIG GET maxmemory-policy` → `noeviction`.
4. **Filesystem:** `docker diff`/`find` without `dump.rdb` or `appendonly.aof` in the
   container.

Inspected values are **not** printed in clear if they could contain data; the test
reports sizes and booleans.

## 3. Step by step

1. Claim in `CLAIMS.md` and branch `s1/j1.6-politica-redis`.
2. Draft `docs/adr/ADR-0005-redis.md` with the §2.1 table (state `proposed`; the sprint
   owner and reviewer mark it `accepted`).
3. Apply the §2.2 configuration in `infra/docker-compose.yml` (coordinated with
   J1.1/J1.5).
4. Write the test with the threshold read from the ADR (shared constant or documented
   parsing).
5. Run:
   ```bash
   cd infra && docker compose up -d redis api worker scheduler
   cd ../apps/api && uv run pytest tests/integration/test_redis_policy.py -m integration -q
   docker compose -f ../infra/docker-compose.yml exec redis sh -lc 'redis-cli INFO persistence | head'
   ```
6. Verify that no volume was added by accident:
   ```bash
   docker compose -f ../infra/docker-compose.yml config --volumes
   ```
7. Record evidence (size summary, configuration, result), logbook and PR.

## 4. Verification and evidence

  persistence and policy `CONFIG GET`, `config --volumes`, and confirmation that no
  sensitive values were printed.
- Attach the link to the ADR and the review decision.

## 5. Coordination and risks

- **ADR-0005 vs L1.2 template:** if L1.2 defines an ADR template, adapt the file without
  changing the decision.
- **4 KiB threshold:** it is a proposal; if ARQ stores larger results, adjust
  `keep_result` or move the data to Postgres; never raise the threshold without
  justifying it in the ADR.
- **`noeviction`:** with memory full, ARQ will fail to enqueue; it must alert (J2.5),
  not silently lose work.
- **Tests dependent on J1.5:** if the dispatcher does not exist yet, the test covers at
  least ARQ + health and the configuration; complete the flows when integrating J1.5.
