## 2. Contract additions

`TaskOut` now exposes two additive fields:

```text
calendar_id: str | None
calendar_event_id: str | None
```

They let the web deduplicate a task against its linked mirror event by identity
`(calendar_id, event_id)` instead of relying only on dates. The fallback remains the event
block for tasks whose link is not available yet.

No calendar endpoint changed. `GET /calendar/events` already returns the mirror events and
the freshness envelope; `GET /tasks` already returns the task blocks.

## 3. Merge rules

`buildCalendarEvents` applies these rules in order:

1. Draw active tasks (`pending`, `needs_review`, `confirmed`) that have an event block.
2. A task with `calendar_id` + `calendar_event_id` claims that event identity.
3. A task without an event ID claims its normalized block (`start|end|allDay`).
4. Draw mirror events only when they are not cancelled/missing and do not collide with a
   claimed event ID or block.
5. Closed tasks (`completed`, `dismissed`) are not drawn, but do not hide their kept Google
   event.
6. Tasks without an event block are counted and reported; no time is invented.
7. Google events use a neutral color; tasks use the subject color with a contrast-aware
   text color.

## 4. UI

- `CalendarView` uses FullCalendar 6.1.22 (`dayGrid` + `timeGrid`), Spanish locale, month
  and week views, and `datesSet` to refetch the visible range.
- `CalendarFreshness` always shows the last synchronization and a closed coverage label:
  `never_synced`, `no_read_calendars`, `calendar_set_changed`, `outside_coverage`, `stale`.
- Legend shows Google and the subjects actually present.
- A compact count strip (`en el rango`, `tareas dibujadas`, `sin bloque`) and a list of tasks
  without an agenda block make the page tangible even when the mirror is empty.
- FullCalendar is restyled to the terminal palette (gold controls, square grid, readable
  events) instead of its default theme.
- Task fetch failure leaves Google events visible with an explicit warning.
- Calendar fetch failure shows a retry action and, when coverage is incomplete, a link to
  the Calendar settings.
- `AgendaPage` is the full agenda; `DashboardPage` embeds the compact calendar.
- No audio, upload, drag/drop, or Calendar write exists.
