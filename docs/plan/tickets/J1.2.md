## 1. Ficha del ticket

- **Objetivo:** que el contenedor `ingest` corra con root filesystem read-only, `tmpfs`
  privado acotado, usuario no root, límites de CPU/memoria y sin swap ni core dumps, con
  `ffmpeg`/`ffprobe` disponibles.
- **Alcance:** target endurecido del `apps/ingest/Dockerfile`, sección endurecida del servicio
  `ingest` en `infra/docker-compose.yml`, verificación **dentro y fuera** del contenedor.
- **No alcance:** reserva real de RAM por slot y benchmark (S1.B2), supervisor/lease/cleanup
  (S1.B3), límites efectivos D4 (spike S1.A5), routing de Caddy (J1.3).
- **Dependencia tipada:** `código` J1.1 (compose y Dockerfile base); `contrato` límites
  provisionales de `.env.example` (`INGEST_TMPFS_BYTES`, `INGEST_SLOTS`).
- **Entregables:** `apps/ingest/Dockerfile` con stage `runtime`; bloque endurecido del servicio
  `ingest` en `infra/docker-compose.yml`; checklist de verificación con comandos.
- **Criterios de aceptación:**
  - [ ] `docker inspect` muestra `ReadonlyRootfs=true`, usuario no root, `CapDrop=ALL`,
    `no-new-privileges`, límites de memoria/CPU y `Tmpfs` acotado.
  - [ ] Dentro del contenedor: `/` es read-only, `TMPDIR` apunta al `tmpfs`, `ffmpeg -version`
    y `ffprobe -version` responden, `ulimit -c` es `0`.
  - [ ] En el host: sin swap activo para el contenedor (`memory.swap.max=0` o equivalente) y
    `core_pattern` que no capture volcados.
  - [ ] Ningún bind mount persistente; los temporales desaparecen al recrear el contenedor.
- **Pruebas/evidencia:** I-S1-SG-06 (S1.B1/B5) para la ausencia de audio; este ticket aporta la
  evidencia de endurecimiento dentro/fuera. Registrar comandos, fecha, entorno y resultado.
- **Archivos previstos:** `apps/ingest/Dockerfile`, `infra/docker-compose.yml` (sección
  `ingest`), `docs/plan/tickets/J1.2.md` (este plan) y la fila de bitácora.

## 2. Diseño de la entrega

### 2.1 Stages del Dockerfile

```dockerfile
# base (J1.8): python fijado por L1.1 + ffmpeg/ffprobe + venv con uv
FROM python:3.12-slim AS base
# ... uv sync --frozen --no-dev, COPY maulwurf_ingest, TMPDIR=/work/tmp

# runtime (J1.2): endurecido
FROM base AS runtime
RUN useradd --uid 10001 --create-home --home-dir /home/app app
ENV TMPDIR=/work/tmp PYTHONDONTWRITEBYTECODE=1
WORKDIR /app
USER 10001:10001
EXPOSE 8000
```

- `ingest` no escribe en `/`; cache de Python y temporales van a `TMPDIR` (`/work/tmp`).
- `ffmpeg` corre sin red (el filtrado de red no se hace en Docker; la regla es «ffmpeg sin
  acceso a red por argv», S2.2) y con límites de salida/tiempo en la app (S2).
- El stage `base` lo entrega J1.8 y lo consume J1.1; J1.2 **no** bloquea el spike (ya
  ejecutado por S1.A con ffmpeg local).

### 2.2 Sección endurecida del compose

```yaml
  ingest:
    build: { context: .., dockerfile: apps/ingest/Dockerfile, target: runtime }
    user: "10001:10001"
    read_only: true
    tmpfs:
      - /work/tmp:rw,noexec,nosuid,nodev,size=${INGEST_TMPFS_BYTES:-268435456}
    cap_drop: [ALL]
    security_opt: [no-new-privileges:true]
    pids_limit: 128
    mem_limit: ${INGEST_MEM_LIMIT:-1g}
    memswap_limit: ${INGEST_MEM_LIMIT:-1g}   # igual a mem_limit => sin swap
    mem_swappiness: 0
    cpus: 2
    ulimits:
      core: 0
      nofile: { soft: 1024, hard: 1024 }
    stop_grace_period: 30s
```

- `INGEST_TMPFS_BYTES` y `INGEST_MEM_LIMIT` se toman del entorno; los valores de
  `.env.example` son **provisionales** y no se aprueban hasta S1.B2/D4.
- El `tmpfs` debe ser privado por contenedor (no `volume` compartido). En reinicio de host se
  pierde por diseño.
- `noexec` en tmpfs no aplica al binario `ffmpeg` (vive en `/usr`), solo a lo escrito allí.

### 2.3 Verificación en el host

- cgroup v2: `memory.swap.max` del contenedor en `0` (o `memory.memsw.limit_in_bytes`
  equivalente en v1); comprobar `cat /sys/fs/cgroup/.../memory.swap.max`.
- `swapon --show` en el host (no debe haber swap activo para la política de ingesta).
- `cat /proc/sys/kernel/core_pattern` y `ulimit -c` del proceso; si el host usa
  `systemd-coredump`, verificar que el contenedor tiene `core: 0` y que no se generan dumps.
- Snapshots/hibernación: revisar el plano de la máquina (VPS local) y anotarlo como
  pendiente de operación si no es inspeccionable.

   ```bash
   cd infra && docker compose build ingest && docker compose up -d ingest
   ```
6. Verificar fuera:
   ```bash
   CID=$(docker compose ps -q ingest)
   docker inspect "$CID" --format '{{.HostConfig.ReadonlyRootfs}} {{.Config.User}} {{json .HostConfig.CapDrop}} {{json .HostConfig.SecurityOpt}}'
   docker inspect "$CID" --format '{{json .HostConfig.Tmpfs}} {{.HostConfig.MemorySwap}} {{.HostConfig.PidsLimit}}'
   cat /sys/fs/cgroup/system.slice/docker-"$CID".scope/memory.swap.max 2>/dev/null
   swapon --show
   ```
7. Verificar dentro (debe fallar la escritura en `/`, no en `TMPDIR`):
   ```bash
   docker compose exec ingest sh -lc 'id; findmnt -no OPTIONS /; touch /x'   # esperado: error
   docker compose exec ingest sh -lc 'touch "$TMPDIR/x" && ls -l "$TMPDIR/x" && rm "$TMPDIR/x"'
   docker compose exec ingest sh -lc 'ffmpeg -version | head -1; ffprobe -version | head -1; ulimit -c'
   ```
8. Confirmar que no hay bind mounts ni volúmenes:
   ```bash
   docker inspect "$CID" --format '{{json .Mounts}}'
   ```
9. Registrar evidencia redactada, actualizar la fila de bitácora y abrir PR.

## 4. Verificación y evidencia

- **Evidencia de endurecimiento:** salidas de `docker inspect` (campos anteriores), `findmnt`,
  `id`, prueba de escritura fallida en `/`, `ulimit -c`, versiones de ffmpeg/ffprobe.
- **Evidencia de privacidad (compartida con S1.B5):** al finalizar S1.B5, barrido de
  descriptores, procesos, mounts, Redis, logs y cachés sin audio. Este ticket deja el
  contenedor configurado; no sustituye I-S1-SG-06.
- Distinguir en la bitácora «endurecimiento verificado» (J1.2) de «target base con ffmpeg»
  (J1.8); el spike S1.A ya se ejecutó sin imagen.

## 5. Coordinaciones y riesgos

- **Conflicto de archivo con J1.1/J1.8:** los tres tocan `apps/ingest/Dockerfile` y el compose.
  Secuencia sugerida: J1.8 (base) → J1.1 (compose) → J1.2 (runtime). Un PR por ticket con
  rebase y review cruzada.
- **`read_only` rompe librerías que escriben caché:** fijar `HOME`, `XDG_CACHE_HOME` y
  `TMPDIR` dentro del tmpfs.
- **Swap en el host:** si el host no permite desactivar swap, documentarlo como bloqueo y no
  presentar el ticket como cerrado.
- **Límites provisionales:** no publicarlos como capacidad real; alimentan D4 en S2.
