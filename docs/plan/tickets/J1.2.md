## 1. Ticket summary

- **Objective:** the `ingest` container runs with a read-only root filesystem, private
  bounded `tmpfs`, non-root user, CPU/memory limits, no swap and no core dumps, with
  `ffmpeg`/`ffprobe` available.
- **Scope:** hardened target of `apps/ingest/Dockerfile`, hardened section of the
  `ingest` service in `infra/docker-compose.yml`, verification **inside and outside** the
  container.
- **Out of scope:** real per-slot RAM reservation and benchmark (S1.B2),
  supervisor/lease/cleanup (S1.B3), effective D4 limits (spike S1.A5), Caddy routing
  (J1.3).
- **Typed dependency:** `code` J1.1 (compose and base Dockerfile); `contract`
  provisional `.env.example` limits (`INGEST_TMPFS_BYTES`, `INGEST_SLOTS`).
- **Deliverables:** `apps/ingest/Dockerfile` with a `runtime` stage; hardened block of
  the `ingest` service in `infra/docker-compose.yml`; verification checklist with
  commands.
- **Acceptance criteria:**
  - [ ] `docker inspect` shows `ReadonlyRootfs=true`, non-root user, `CapDrop=ALL`,
    `no-new-privileges`, memory/CPU limits and a bounded `Tmpfs`.
  - [ ] Inside the container: `/` is read-only, `TMPDIR` points to the `tmpfs`,
    `ffmpeg -version` and `ffprobe -version` respond, `ulimit -c` is `0`.
  - [ ] On the host: no active swap for the container (`memory.swap.max=0` or
    equivalent) and a `core_pattern` that does not capture dumps.
  - [ ] No persistent bind mount; temporaries disappear when the container is recreated.
- **Tests/evidence:** I-S1-SG-06 (S1.B1/B5) for the absence of audio; this ticket
  provides the hardening evidence inside/outside. Record commands, date, environment and
  result.
- **Planned files:** `apps/ingest/Dockerfile`, `infra/docker-compose.yml` (`ingest`
  section), `docs/plan/tickets/J1.2.md` (this plan) and the logbook row.

## 2. Delivery design

### 2.1 Dockerfile stages

```dockerfile
# base (J1.8): python pinned by L1.1 + ffmpeg/ffprobe + venv with uv
FROM python:3.12-slim AS base
# ... uv sync --frozen --no-dev, COPY maulwurf_ingest, TMPDIR=/work/tmp

# runtime (J1.2): hardened
FROM base AS runtime
RUN useradd --uid 10001 --create-home --home-dir /home/app app
ENV TMPDIR=/work/tmp PYTHONDONTWRITEBYTECODE=1
WORKDIR /app
USER 10001:10001
EXPOSE 8000
```

- `ingest` does not write to `/`; Python cache and temporaries go to `TMPDIR`
  (`/work/tmp`).
- `ffmpeg` runs without network (network filtering is not done in Docker; the rule is
  "ffmpeg without network access by argv", S2.2) and with output/time limits in the app
  (S2).
- The `base` stage is delivered by J1.8 and consumed by J1.1; J1.2 **does not** block the
  spike (already executed by S1.A with local ffmpeg).

### 2.2 Hardened compose section

```yaml
  ingest:
    build: { context: .., dockerfile: apps/ingest/Dockerfile, target: runtime }
    user: "10001:10001"
    read_only: true
    tmpfs:
      - /work/tmp:rw,noexec,nosuid,nodev,size=${INGEST_TMPFS_BYTES:-268435456}
    cap_drop: [ALL]
    security_opt: [no-new-privileges:true]
    pids_limit: 128
    mem_limit: ${INGEST_MEM_LIMIT:-1g}
    memswap_limit: ${INGEST_MEM_LIMIT:-1g}   # equal to mem_limit => no swap
    mem_swappiness: 0
    cpus: 2
    ulimits:
      core: 0
      nofile: { soft: 1024, hard: 1024 }
    stop_grace_period: 30s
```

- `INGEST_TMPFS_BYTES` and `INGEST_MEM_LIMIT` are taken from the environment; the
  `.env.example` values are **provisional** and are not approved until S1.B2/D4.
- The `tmpfs` must be private per container (no shared `volume`). It is lost by design
  on a host restart.
- `noexec` on tmpfs does not apply to the `ffmpeg` binary (it lives in `/usr`), only to
  what is written there.

### 2.3 Verification on the host

- cgroup v2: container `memory.swap.max` at `0` (or `memory.memsw.limit_in_bytes`
  equivalent on v1); check `cat /sys/fs/cgroup/.../memory.swap.max`.
- `swapon --show` on the host (there must be no active swap for the ingestion policy).
- `cat /proc/sys/kernel/core_pattern` and the process `ulimit -c`; if the host uses
  `systemd-coredump`, verify the container has `core: 0` and that no dumps are
  generated.
- Snapshots/hibernation: review the machine plan (local VPS) and note it as pending for
  operations if it cannot be inspected.

## 3. Step by step

1. Claim in `CLAIMS.md` (`claim` action, area J-) and branch `s1/j1.2-ingest-hardening`.
2. If J1.8 has not yet delivered the `base` target, coordinate it or create it as part
   of the same Dockerfile without replacing its check (`ffmpeg -version`).
3. Add the `runtime` stage with a non-root user and `TMPDIR` on tmpfs.
4. Update the `ingest` section of the compose with the §2.2 controls.
5. Build and start:
   ```bash
   cd infra && docker compose build ingest && docker compose up -d ingest
   ```
6. Verify outside:
   ```bash
   CID=$(docker compose ps -q ingest)
   docker inspect "$CID" --format '{{.HostConfig.ReadonlyRootfs}} {{.Config.User}} {{json .HostConfig.CapDrop}} {{json .HostConfig.SecurityOpt}}'
   docker inspect "$CID" --format '{{json .HostConfig.Tmpfs}} {{.HostConfig.MemorySwap}} {{.HostConfig.PidsLimit}}'
   cat /sys/fs/cgroup/system.slice/docker-"$CID".scope/memory.swap.max 2>/dev/null
   swapon --show
   ```
7. Verify inside (a write to `/` must fail, not one to `TMPDIR`):
   ```bash
   docker compose exec ingest sh -lc 'id; findmnt -no OPTIONS /; touch /x'   # expected: error
   docker compose exec ingest sh -lc 'touch "$TMPDIR/x" && ls -l "$TMPDIR/x" && rm "$TMPDIR/x"'
   docker compose exec ingest sh -lc 'ffmpeg -version | head -1; ffprobe -version | head -1; ulimit -c'
   ```
8. Confirm there are no bind mounts or volumes:
   ```bash
   docker inspect "$CID" --format '{{json .Mounts}}'
   ```
9. Record redacted evidence, update the logbook row and open the PR.

## 4. Verification and evidence

- **Hardening evidence:** `docker inspect` outputs (fields above), `findmnt`, `id`,
  failed write test on `/`, `ulimit -c`, ffmpeg/ffprobe versions.
- **Privacy evidence (shared with S1.B5):** at the end of S1.B5, a sweep of descriptors,
  processes, mounts, Redis, logs and caches without audio. This ticket leaves the
  container configured; it does not replace I-S1-SG-06.
- Distinguish in the logbook "hardening verified" (J1.2) from "base target with ffmpeg"
  (J1.8); the S1.A spike already ran without an image.

## 5. Coordination and risks

- **File conflict with J1.1/J1.8:** all three touch `apps/ingest/Dockerfile` and the
  compose. Suggested sequence: J1.8 (base) → J1.1 (compose) → J1.2 (runtime). One PR per
  ticket with rebase and cross review.
- **`read_only` breaks libraries that write cache:** set `HOME`, `XDG_CACHE_HOME` and
  `TMPDIR` inside the tmpfs.
- **Swap on the host:** if the host does not allow disabling swap, document it as a
  blocker and do not present the ticket as closed.
- **Provisional limits:** do not publish them as real capacity; they feed D4 in S2.
