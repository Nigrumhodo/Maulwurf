## 1. Scope

| In D2.1 | Not in D2.1 |
|---|---|
| Subject/date/timezone/language (no preselection), optional title/teacher | Streaming `PUT` of the bytes (D2.2) |
| Versioned privacy notice + two mandatory acknowledgements before accepting bytes | Ingestion progress / SSE (D2.3) |
| Real capability limits from `/ingestion/capabilities` | Library listing (D2.4) |
| `POST /audios` reservation and error mapping | `409 duplicate_variant` second round trip (A2.5/D2.2) |
| `privacy_notice_version` exposed by capabilities (cross-area, area A) | Real Riva/NVIDIA calls (blocked F0) |

The form **reserves** the class; it does not transfer audio. The confirmation view shows the
reservation ids/expiry and states that no byte has been sent yet.

## 2. Fixed decisions

1. **`privacy_notice_version` in the response.** `GET /ingestion/capabilities` must expose the
   **current** notice version so the form renders exactly what `POST /audios` will validate.
   The field is injected by the endpoint from `settings.privacy_notice_version`; it never
   comes from the published spike JSON. Cross-area change (`apps/api/app/schemas/ingestion.py`,
   `apps/api/app/routers/ingestion.py`) — request an area-A review on the PR.
2. **No provisional limits.** When `limits_validated === false`, the UI shows an honest
   "sin límites publicados" state and **disables** submit. It does not fall back to the
   S1 `es/en/fr` allowlist or the 200 MiB placeholder.
3. **No language preselection** (M2): the select starts empty, options come from
   `capabilities.languages`, and `multi` is never offered.
4. **Consent is client-visible and mandatory**: accepted cloud processing, no
   playback/retranscription, and the server's notice version. `consent_required` from the
   server resets both checkboxes (the notice changed or the version is stale).

## 3. API contract used

- `POST /audios` body (`AudioCreate`): `subject_id`, `class_date`, `class_timezone`,
  `language_code`, `title?`, `teacher?`, `privacy_notice_version`, `cloud_processing_accepted`,
  `third_party_voice_acknowledged`.
- `201 AudioCreated`: `{audio_id, attempt_id, upload_url, upload_expires_at, outcome}`.
- Errors: `422 consent_required{privacy_notice_version}` / `language_not_allowed{allowed}` /
  `validation_failed{fields}`, `404`, `409`, `429` (+`Retry-After`), `503` (+`Retry-After`).
- `GET /ingestion/capabilities`: `IngestionCapabilities` + `privacy_notice_version`.
  `limits_validated=false` → limits `null`/empty.

## 4. Code, step by step

### Step 1 — API (cross-area, area A review)

1. `apps/api/app/schemas/ingestion.py`: add
   `privacy_notice_version: str | None = Field(default=None, min_length=1, max_length=64)` to
   `IngestionCapabilities` (nullable so the config JSON never needs it; the endpoint fills it).
2. `apps/api/app/routers/ingestion.py`: return
   `settings.ingestion_capabilities.model_copy(update={"privacy_notice_version":
   settings.privacy_notice_version})`.
3. `apps/api/tests/unit/test_ingestion_capabilities.py`: the two response assertions include
   `"privacy_notice_version": "2026-09-v1"`.

### Step 2 — Read helpers (web)

1. `apps/web/src/lib/capabilities.ts`: `IngestionCapabilities` type and `fetchCapabilities()`.
2. `apps/web/src/lib/subjects.ts`: add `fetchSubjects()`; `MateriasPage` reuses it.
3. `apps/web/src/components/ui/LanguageSelect.tsx`: optional `options` prop (default
   `LANGUAGES`); D2.1 passes the published codes.

### Step 3 — Pure form logic (`apps/web/src/lib/upload.ts`)

`UploadDraft`, `languageOptions`, `capabilitiesUsable`, `validateUpload`, `buildAudioCreate`
(optional title/teacher → `null`), `uploadFormError` (consent reset, language allowlist,
`validation_failed`, 429/503 advice), `AudioCreated`.

### Step 4 — `apps/web/src/components/upload/UploadForm.tsx`

Load subjects + capabilities in parallel; loading/error/empty-subjects states; limits block
(honest when `limits_validated=false`); the fields; the versioned consent with two
checkboxes; submit disabled without capabilities or consent; on `201` show the reservation
(ids/expiry, "no byte sent yet"); on error map via `uploadFormError` and refetch/override the
language allowlist when the server answers `language_not_allowed`. `SubirClasePage` copy
updated from "draft" to the real reservation flow.

## 7. Risks and open points

| Risk | Mitigation |
|---|---|
| The capabilities field is area A | Keep the change minimal; request area-A review; the web code can mock the field until merged |
| `limits_validated=false` in the current spike | Honest disabled state; no provisional values (guardrail 10) |
| D2.1 reserves but does not send bytes | Explicit confirmation view; D2.2 owns the `PUT`; cancelling an orphan reservation is D2.2/D2.4 |
| `privacy_notice_version` drift | UI renders server value verbatim; on `consent_required` it refetches/resets |
