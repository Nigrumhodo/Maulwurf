## 1. Ticket summary

- **Objective:** deliver the `base` target of `apps/ingest/Dockerfile` with pinned
  `ffmpeg`/`ffprobe`, on which J1.1 (compose) and J1.2 (hardening) depend, and compare
  the effective version inside the image with the 8.0.1 used in the S1.A spike evidence.
- **Scope:** `base` stage of `apps/ingest/Dockerfile` with ffmpeg/ffprobe, package
  dependencies, reproducible version check and parity note with the spike.
- **Out of scope:** read-only root filesystem, tmpfs, no root and limits (J1.2); real
  reception, validator and fragmenter (S2); Riva calls (S1.A2+, protected); re-running
  the spike (already executed and evidenced).
- **Typed dependency:** `code` J1.1 (compose consumes it with `target: base`);
  `contract` Python/image version pinned by L1.1.
- **Deliverables:** `apps/ingest/Dockerfile` (`base` stage); evidence of
  `ffmpeg -version` and `ffprobe -version` **inside** the image, plus the immutable
  tag/digest used.
- **Acceptance criteria:**
  - [ ] `docker build --target base` finishes without errors and without secrets.
  - [ ] `ffmpeg -version` and `ffprobe -version` run inside the image and are recorded.
  - [ ] The image contains no audio or private data; the build context excludes `.env`.
  - [ ] The explicit comparison with the spike's 8.0.1 version is recorded (match or a
    documented effect/re-probe plan).
- **Tests/evidence:** the ticket's "Mandatory verification" (versions inside the image,
  comparison with 8.0.1 + digest). Do not confuse with I-S1-SG-06 (hardening, J1.2).
- **Planned files:** `apps/ingest/Dockerfile`, `infra/docker-compose.yml`
  (`target: base` reference, coordinated with J1.1).

## 2. Delivery design

### 2.1 Dockerfile (base stage)

```dockerfile
# syntax=docker/dockerfile:1
FROM python:3.12-slim@sha256:<digest pinned by L1.1> AS base

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    UV_PROJECT_ENVIRONMENT=/opt/venv \
    TMPDIR=/work/tmp

RUN apt-get update \
 && apt-get install -y --no-install-recommends ffmpeg ca-certificates \
 && rm -rf /var/lib/apt/lists/*

COPY --from=ghcr.io/astral-sh/uv:<pinned version> /uv /usr/local/bin/uv
WORKDIR /app
COPY apps/ingest/pyproject.toml apps/ingest/uv.lock ./
RUN uv sync --frozen --no-dev --no-install-project
COPY apps/ingest/maulwurf_ingest ./maulwurf_ingest
ENV PATH="/opt/venv/bin:$PATH"

# J1.2 adds the hardened runtime stage; base stays intact for the spike.
```

Notes:

- The build context is the repo root (it needs the app's `pyproject.toml` and
  `uv.lock`). Add/verify `apps/ingest/.dockerignore` to exclude `.env`, `tests`, caches
  and artifacts; **never** copy audio.
- `ca-certificates` is needed for gRPC/TLS to Riva in the spike (S1.A2, protected).
- Debian's `ffmpeg` may be older than the host's: **the version that counts is the one
  in the image** and it must be recorded. If it does not match the spike's 8.0.1, decide
  between pinning an image/package with ffmpeg 8.x, re-running the format probes inside
  the image or documenting the effect on S1.A4/S2; do not leave it implicit.
- `TMPDIR` is used for test temporaries; in `base` there is no guaranteed `tmpfs` (that
  is J1.2). Even so, persisting audio is forbidden: any test WAV is generated in RAM
  inside the container or in an ephemeral `tmpfs`, never versioned or bind-mounted from
  the host.

### 2.2 Use of the `base` stage (no-persistence rule)

- Suggested run without durable audio:
  ```bash
  docker run --rm -it --tmpfs /work/tmp:rw,size=512m \
    maulwurf-ingest:base bash -lc 'python -c "from maulwurf_ingest..."; ffmpeg -version | head -1'
  ```
- Any synthetic WAV is generated on the spot, in ephemeral `/work/tmp` or in RAM; it is
  not copied to the host nor kept as an artifact.

## 3. Step by step

1. Claim in `CLAIMS.md` and branch `s1/j1.8-ingest-base-ffmpeg`.
2. Confirm with L1.1 the Python/base image and `uv` versions; capture the digest:
   ```bash
   docker pull python:3.12-slim && docker inspect --format '{{index .RepoDigests 0}}' python:3.12-slim
   ```
3. Create `apps/ingest/Dockerfile` with the `base` stage and
   `apps/ingest/.dockerignore`.
4. Build:
   ```bash
   docker build -f apps/ingest/Dockerfile --target base -t maulwurf-ingest:base .
   ```
5. Check the versions inside the image and compare them with the spike evidence:
   ```bash
   docker run --rm maulwurf-ingest:base ffmpeg -version | head -1
   docker run --rm maulwurf-ingest:base ffprobe -version | head -1
   docker run --rm maulwurf-ingest:base python -c 'import maulwurf_ingest, sys; print(sys.version)'
   # compare against the ffmpeg/ffprobe 8.0.1 of S1.A4/A5
   ```
6. Decide and record the version parity (pin 8.x, re-run the probes or document the
   effect), linking the conclusion with S1.A4/S2.
7. Record the immutable identity:
   ```bash
   docker inspect --format '{{.Id}}' maulwurf-ingest:base
   docker images --digests maulwurf-ingest
   ```
8. Integrate with J1.1 (compose points at `target: base`) and verify the service
   starts.
9. Record evidence, logbook and PR.

## 5. Coordination and risks

- **File shared with J1.1/J1.2:** the Dockerfile evolves through separate PRs; J1.8
  delivers the `base` target that J1.1 consumes and J1.2 hardens.
- **Image size:** `ffmpeg` adds hundreds of MB; acceptable locally, to be optimized in
  J1.2+ if necessary (without breaking functionality).
- **ffmpeg version different from the spike's:** explicit decision in step 6; it
  affects the format table (S1.A4) and the S2 parsers.
- **No secrets in build args:** `NVIDIA_API_KEY` does not enter the image; it is
  injected at runtime only for authorized tests.
