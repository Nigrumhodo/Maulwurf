## 1. Ficha del ticket

- **Objetivo:** entregar el target `base` de `apps/ingest/Dockerfile` con `ffmpeg`/`ffprobe`
  fijados, del que dependen J1.1 (compose) y J1.2 (endurecimiento), y comparar la versión
  efectiva dentro de la imagen con la 8.0.1 usada en la evidencia del spike S1.A.
- **Alcance:** stage `base` de `apps/ingest/Dockerfile` con ffmpeg/ffprobe, dependencias del
  paquete, comprobación reproducible de versiones y nota de paridad con el spike.
- **No alcance:** root filesystem read-only, tmpfs, no root y límites (J1.2); recepción real,
  validador y fragmentador (S2); llamadas a Riva (S1.A2+, protegidas); re-empujar el spike
  (ya ejecutado y evidenciado).
- **Dependencia tipada:** `código` J1.1 (compose lo consume con `target: base`); `contrato`
  versión de Python/imagen fijada por L1.1.
- **Entregables:** `apps/ingest/Dockerfile` (stage `base`); evidencia de `ffmpeg -version` y
  `ffprobe -version` **dentro** de la imagen, más tag/digest inmutable usado.
- **Criterios de aceptación:**
  - [ ] `docker build --target base` termina sin errores y sin secretos.
  - [ ] `ffmpeg -version` y `ffprobe -version` corren dentro de la imagen y quedan registrados.
  - [ ] La imagen no contiene audio ni datos privados; el contexto de build no incluye `.env`.
  - [ ] Queda registrada la comparación explícita con la versión 8.0.1 del spike (coincide o
    se documenta el efecto/plan de re-probe).
- **Pruebas/evidencia:** «Verificación obligatoria» del ticket (versiones dentro de la imagen,
  comparación con 8.0.1 + digest). No confundir con I-S1-SG-06 (hardening, J1.2).
- **Archivos previstos:** `apps/ingest/Dockerfile`, `infra/docker-compose.yml` (referencia
  `target: base`, coordinado con J1.1).

## 2. Diseño de la entrega

### 2.1 Dockerfile (stage base)

```dockerfile
# syntax=docker/dockerfile:1
FROM python:3.12-slim@sha256:<digest fijado por L1.1> AS base

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    UV_PROJECT_ENVIRONMENT=/opt/venv \
    TMPDIR=/work/tmp

RUN apt-get update \
 && apt-get install -y --no-install-recommends ffmpeg ca-certificates \
 && rm -rf /var/lib/apt/lists/*

COPY --from=ghcr.io/astral-sh/uv:<version fijada> /uv /usr/local/bin/uv
WORKDIR /app
COPY apps/ingest/pyproject.toml apps/ingest/uv.lock ./
RUN uv sync --frozen --no-dev --no-install-project
COPY apps/ingest/maulwurf_ingest ./maulwurf_ingest
ENV PATH="/opt/venv/bin:$PATH"

# J1.2 agrega el stage runtime endurecido; base queda intacto para el spike.
```

Notas:

- El contexto de build es la raíz del repo (necesita `pyproject.toml` y `uv.lock` de la app).
  Agregar/verificar `apps/ingest/.dockerignore` para excluir `.env`, `tests`, caches y
  artefactos; **nunca** copiar audio.
- `ca-certificates` es necesario para gRPC/TLS a Riva en el spike (S1.A2, protegido).
- `ffmpeg` de Debian puede ser más antiguo que el del host: **la versión que cuenta es la de
  la imagen** y debe registrarse. Si no coincide con la 8.0.1 del spike, decidir entre fijar
  una imagen/paquete con ffmpeg 8.x, re-ejecutar los probes de formato dentro de la imagen o
  documentar el efecto sobre S1.A4/S2; no dejarlo implícito.
- El `TMPDIR` se usa para temporales de pruebas; en `base` no hay `tmpfs` garantizado (eso es
  J1.2). Aun así, está prohibido persistir audio: cualquier WAV de prueba se genera en RAM
  dentro del contenedor o en un `tmpfs` efímero, nunca versionado ni bind-mounted desde el
  host.

### 2.2 Uso del stage `base` (regla de no persistencia)

- Ejecución sugerida sin audio durable:
  ```bash
  docker run --rm -it --tmpfs /work/tmp:rw,size=512m \
    maulwurf-ingest:base bash -lc 'python -c "from maulwurf_ingest..."; ffmpeg -version | head -1'
  ```
- Cualquier WAV sintético se genera en el momento, en `/work/tmp` efímero o en RAM; no se
  copia al host ni queda como artefacto.

## 3. Paso a paso

1. Claim en `CLAIMS.md` y rama `s1/j1.8-ingest-base-ffmpeg`.
2. Confirmar con L1.1 la versión de Python/imagen base y de `uv`; capturar el digest:
   ```bash
   docker pull python:3.12-slim && docker inspect --format '{{index .RepoDigests 0}}' python:3.12-slim
   ```
3. Crear `apps/ingest/Dockerfile` con el stage `base` y `apps/ingest/.dockerignore`.
4. Construir:
   ```bash
   docker build -f apps/ingest/Dockerfile --target base -t maulwurf-ingest:base .
   ```
5. Comprobar versiones dentro de la imagen y compararlas con la evidencia del spike:
   ```bash
   docker run --rm maulwurf-ingest:base ffmpeg -version | head -1
   docker run --rm maulwurf-ingest:base ffprobe -version | head -1
   docker run --rm maulwurf-ingest:base python -c 'import maulwurf_ingest, sys; print(sys.version)'
   # comparar contra ffmpeg/ffprobe 8.0.1 de S1.A4/A5
   ```
6. Decidir y registrar la paridad de versión (fijar 8.x, re-ejecutar probes o documentar el
   efecto), enlazando la conclusión con S1.A4/S2.
7. Registrar identidad inmutable:
   ```bash
   docker inspect --format '{{.Id}}' maulwurf-ingest:base
   docker images --digests maulwurf-ingest
   ```
8. Integrar con J1.1 (compose apunta a `target: base`) y verificar que el servicio arranca.
9. Registrar evidencia, bitácora y PR.

## 5. Coordinaciones y riesgos

- **Archivo compartido con J1.1/J1.2:** el Dockerfile evoluciona por PRs separados; J1.8
  entrega el target `base` que J1.1 consume y J1.2 endurece.
- **Tamaño de imagen:** `ffmpeg` suma cientos de MB; aceptable en local, se optimizará en J1.2+
  si es necesario (sin romper la funcionalidad).
- **Versión de ffmpeg distinta a la del spike:** decisión explícita del paso 6; afecta la
  tabla de formatos (S1.A4) y los parsers de S2.
- **Sin secretos en build args:** `NVIDIA_API_KEY` no entra a la imagen; se inyecta en runtime
  solo para pruebas autorizadas.
