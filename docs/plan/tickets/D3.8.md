## 2. Contract additions

- SSE `tool` event: `{name, ok, payload}` where `payload` is the closed tool projection
  (`CalendarToolPayload`, `PendingTasksPayload`, `ProposalPayload` or `ToolErrorPayload`).
- `done.tools`: the full list of `{name, ok, payload}` for the turn.
- `done.proposals`: the `ProposalPayload` entries created by `propose_task`.
- `MessageOut.tool_calls`: the persisted list, so history reload keeps the badges/cards.
- Migration `0022_s3_chat_tool_calls`: `messages.tool_calls JSONB NOT NULL DEFAULT '[]'`.
  `message_sources` keeps its transcript-only meaning.

## 3. Behavior

- `chat_tools.py` adds a strict JSON protocol: the model answers normally or emits exactly
  one `{"tool": "<name>", "arguments": {...}}` object. The server executes it, appends a
  `Tool result` message and repeats, bounded by `MAX_TOOL_ROUNDS=4` and
  `TOOL_BUDGET_SECONDS=15` from `tools.py`.
- A malformed tool object is treated as prose; a tool failure is a closed
  `{code: "tool_failed"}` payload; an invalid tool call is rejected by the orchestrator.
- `propose_task` creates a `needs_review` task with `source=chat`; no Calendar event, no
  outbox and no email. A general suggestion uses `sources: []` and
  `evidence=general_suggestion`.
- The UI labels `get_calendar_events` as “según tu agenda” and `get_pending_tasks` as
  “según tus tareas”; `propose_task` renders an inbox card with “no se escribió en
  Calendar” and a link to `/gestion/tareas`, with no confirm button in the chat.
- The restored `ChatWorkspace`/`Citation`/`MarkdownBody` keep the D2.6/D2.7 chat surface;
  `ChatPage` is the only conversation screen.
