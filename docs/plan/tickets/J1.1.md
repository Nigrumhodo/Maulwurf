## 1. Ticket summary

- **Objective:** deliver an `infra/docker-compose.yml` that brings up the `web`, `api`,
  `ingest`, `worker`, `scheduler`, `postgres` (pinned pgvector), `redis` and `caddy`
  services, with no volume or mount that persists audio.
- **Scope:** compose, networks, internal healthchecks, base Dockerfiles for `api` and
  `web`, optional `env_file`, image pinning by digest.
- **Out of scope:** hardening `ingest` (J1.2), final Caddyfile (J1.3), CI (J1.4), real
  dispatcher and `/readyz` (J1.5), Redis policy (J1.6), migrations (A1.7), real ingestion

- **Typed dependency:** `code` J1.1 ← L1.1 (versions and lockfiles pinned).
  **L1.1 is `hecho`** (pins in [../../VERSIONES.md](../../VERSIONES.md), ADR-0002): use
  Python 3.12, Node 22 and `pgvector/pgvector:pg16` as-is; do not introduce new numbers.
- **Operational dependency:** Docker Engine + Compose v2 on the owner's machine.
- **Deliverables:** `infra/docker-compose.yml`, `apps/api/Dockerfile`,
  `apps/web/Dockerfile`, a minimal provisional `infra/Caddyfile` (J1.3 replaces it), and a
  minimal `ingest` entrypoint so the service can start (see §5).

  - [ ] `docker compose up -d --build --wait` leaves the 8 services `healthy`.
  - [ ] `pgvector/pgvector:pg16` is pinned by digest in addition to the tag.
  - [ ] No volume, bind or persistent tmpfs holding audio exists; `docker compose config`

  - [ ] `worker`/`scheduler` use the same image as `api` with a different command.
- **Tests/evidence:** I-S1-JF-01 (compose smoke of the 8 services) — the `/readyz` part is

## 2. Delivery design

### 2.1 Topology

```mermaid
flowchart LR
    B[Browser] -->|443 TLS| C[caddy]
    C --> W[web:3000]
    C --> A[api:8000]
    C --> I[ingest:8000]
    A --- P[(postgres)]
    A --- R[(redis)]
    I --- P
    WK[worker] --- R
    WK --- P
    SC[scheduler] --- R
    SC --- P
```

- `edge` network: `caddy`, `web`, `api`, `ingest`.
- `data` network: `postgres`, `redis`, `api`, `ingest`, `worker`, `scheduler`.
- Only `caddy` publishes ports (`80`, `443`). Healthchecks run **inside** each container;
  Caddy does not publish `/healthz`.

### 2.2 Volumes (privacy rule)

| Volume | Use | Audio? |
|---|---|---|
| `pgdata` | PostgreSQL data | no |
| `caddy_data` | local CA and certificates | no |
| `caddy_config` | Caddy autosave | no |
| — | Redis | no volume by default; J1.6/ADR-0005 decides persistence |

Forbidden: bind mounts to `apps/ingest`, the host `/tmp`, upload folders or any path that
could contain audio. Ingestion temporaries are private per-container `tmpfs` (J1.2).

### 2.3 Environment variables

- `env_file: ../.env` with `required: false` (the repo does not commit `.env`).
- `MAULWURF_DATABASE_URL` and `MAULWURF_REDIS_URL` are **overridden** in compose with the
  service names (`postgres`, `redis`), as `.env.example` warns.
- Provider secrets (`NVIDIA_API_KEY`, `GOOGLE_*`) are not declared as explicit
  `environment`; they enter only through the local `env_file`. Never in the versioned
  compose or in logs.

### 2.4 Healthchecks

| Service | Check | Command |
|---|---|---|
| `postgres` | `pg_isready -U maulwurf -d maulwurf` | shell |
| `redis` | `redis-cli ping` | shell |
| `api` | `GET /healthz` with Python stdlib | `python -c "import urllib.request;..."` |
| `ingest` | `GET /healthz` same | same |
| `web` | `fetch('http://127.0.0.1:3000/')` with Node | `node -e "..."` |
| `worker`/`scheduler` | Redis ping + ARQ health key | `python -m app.workers.health` (J1.5) |
| `caddy` | not required (fast process, depends on the three being healthy) | — |

API and ingest `/readyz` are wired up in J1.5/A; J1.1 only guarantees `/healthz`.

### 2.5 Images and Dockerfiles

- `postgres`: `pgvector/pgvector:pg16@sha256:<digest captured at implementation>`.
- `redis`: `redis:7.4-alpine@sha256:<digest>` with the J1.6 policy command (no
  persistence by default).
- `caddy`: `caddy:2.8-alpine@sha256:<digest>`.
- `api`/`worker`/`scheduler`: a single `maulwurf-api:local` image (build
  `apps/api/Dockerfile`, target `runtime`); `worker` and `scheduler` change only the
  `command`.
- `ingest`: `apps/ingest/Dockerfile` target `base` from J1.8; J1.2 adds the hardened
  `runtime` target and updates the compose.
- `web`: `apps/web/Dockerfile` (Node LTS pinned by L1.1), `npm ci` + `npm run build` +
  `npm run start`, non-root user.

## 3. Step by step

1. **Claim first:** atomic PR to `docs/sprints/CLAIMS.md` (`claim` action, single owner,
   `claimed_at` UTC, eligibility `no aplica`, reviewers from area J or the lead).
2. Create branch `s1/j1.1-docker-compose` from an up-to-date `develop` (base per
   ADR-0004).
3. Capture the real digests:
   ```bash
   docker pull pgvector/pgvector:pg16 && docker inspect --format '{{index .RepoDigests 0}}' pgvector/pgvector:pg16
   docker pull redis:7.4-alpine && docker inspect --format '{{index .RepoDigests 0}}' redis:7.4-alpine
   docker pull caddy:2.8-alpine && docker inspect --format '{{index .RepoDigests 0}}' caddy:2.8-alpine
   ```
4. Write `apps/api/Dockerfile` (multi-stage, `uv sync --frozen --no-dev`,
   `uvicorn app.main:app`, no root). Do not copy `alembic.ini` until A1.7 delivers it.
5. Write `apps/web/Dockerfile`.
6. Confirm with the ingestion owner the minimal entrypoint (`/healthz`) and build the
   image from the J1.8 target; if J1.8 does not exist yet, agree on who advances it.
7. Write `infra/docker-compose.yml` with the §2 design and a minimal `infra/Caddyfile`
   (`tls internal`, routes to `web`, `api` and `ingest`); J1.3 hardens it.
8. Bring up and wait for health:
   ```bash
   cd infra && docker compose up -d --build --wait
   docker compose ps --format json
   docker compose exec api python -c "import urllib.request;print(urllib.request.urlopen('http://localhost:8000/healthz').status)"
   ```
9. Audit the absence of audio and of persistent mounts:
   ```bash
   docker compose config --volumes
   docker inspect $(docker compose ps -q ingest) --format '{{json .Mounts}}'
   ```
10. `docker compose down` and record evidence (UTC date, environment, versions, digests,
    `compose ps` output) in the logbook; open the PR.
