## 1. Ticket summary

- **Objective:** document reproducible commands to bring up, test, lint and migrate the
  project, so that a person without context can clone and start without asking.
- **Scope:** `docs/RUNBOOK-dev.md` (canonical document) and a link from the root
  `README.md`; update of the repo status only when it is true.
- **Out of scope:** production/deployment runbooks (S4/J4.7), provider troubleshooting,
  endpoint documentation (A1.8/OpenAPI).
- **Typed dependency:** `code` J1.1 (compose), `code` A1.7 (Alembic commands), `code`
  J1.4 (lint/test commands if they change). If A1.7 does not exist, document the command
  as pending and do not invent paths.
- **Deliverables:** `docs/RUNBOOK-dev.md`; a "Local development" section in `README.md`
  with a link; a redacted transcript of a clean checkout.
- **Acceptance criteria:**
  - [ ] A clean clone follows the runbook from start to finish with no undocumented
    manual steps.
  - [ ] The bring-up, test, lint and migration commands are tested and dated.
  - [ ] The `README.md` links the runbook and its status section asserts nothing
    unverified.
  - [ ] No command prints secrets and the runbook contains no real values.
- **Tests/evidence:** "Mandatory verification" of S1.md: transcribe the run from a clean
  environment (command, date, environment, result), redacted.
- **Planned files:** `docs/RUNBOOK-dev.md`, `README.md`.

## 2. Delivery design

### 2.1 Content of `docs/RUNBOOK-dev.md`

1. **Requirements:** Docker Engine + Compose v2, `uv`, Node LTS, `openssl`; the versions
   pinned by L1.1 are in [../../VERSIONES.md](../../VERSIONES.md) (Python 3.12.14,
   Node 22.20.0).
2. **Prepare the environment:**
   ```bash
   git clone <repo> && cd Maulwurf
   cp .env.example .env
   # generate local secrets without printing them in the shell history
   openssl rand -hex 32   # MAULWURF_SECRET_KEY
   openssl rand -hex 32   # MAULWURF_ENCRYPTION_KEY
   openssl rand -hex 32   # MAULWURF_OAUTH_STATE_SECRET
   ```
3. **Bring everything up:**
   ```bash
   cd infra && docker compose up -d --build --wait && docker compose ps
   ```
4. **Local TLS:** the Caddy CA lives in `caddy_data`; trust it or use `curl -k`;
   explain the browser warning and how to trust the CA (command/UI), without lowering
   the TLS guard in production.
5. **Migrations (once A1.7 exists):**
   ```bash
   docker compose exec api alembic upgrade head
   docker compose exec api alembic current
   ```
6. **Healthchecks:**
   ```bash
   curl -kI https://localhost/
   curl -k https://localhost/me        # 401 without session
   docker compose logs -f api
   ```
7. **Tests and lint:**
   ```bash
   cd apps/api   && uv sync --extra dev && uv run pytest -m "not integration and not provider and not load"
   cd apps/ingest && uv sync --extra dev && uv run pytest -m "not integration and not provider and not load"
   cd apps/api   && uv run ruff check . && uv run mypy .
   cd apps/web   && npm ci && npm run lint && npm run typecheck && npm run test && npm run build
   ```
8. **Local integration (real services):** bring up `postgres`/`redis` and run
   `pytest -m integration` with `MAULWURF_DATABASE_URL`/`MAULWURF_REDIS_URL` pointing at
   compose.
9. **Shut down / clean up:** `docker compose down` (keeps `pgdata`) and `down -v`
   (destructive, explicit warning); remember there is **no persisted audio to delete**.
10. **Troubleshooting:** ports 80/443 in use, secrets with `change-me` (fail-fast of
    `app/core/config.py`), untrusted CA, slow first build.
11. **Links:** ADRs, `ESPECIFICACION.md`, `PLAN_SPRINTS.md`, test catalog, logbooks.

2. Collect the real commands from J1.1/J1.4/A1.7 and test them one by one in the local

5. Validate from a clean checkout:
   ```bash
   git clone <path-or-url> /tmp/maulwurf-runbook-check
   cd /tmp/maulwurf-runbook-check
   # follow the runbook step by step and capture the transcript
   ```
6. Transcript rules: no `.env`, no cookies, no tokens, no audio; redact sensitive
   values and headers.
