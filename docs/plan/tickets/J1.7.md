## 1. Ficha del ticket

- **Objetivo:** documentar comandos reproducibles para levantar, probar, lintar y migrar el
  proyecto, de modo que una persona sin contexto pueda clonar y arrancar sin preguntar.
- **Alcance:** `docs/RUNBOOK-dev.md` (documento canónico) y enlace desde el `README.md` raíz;
  actualización del estado del repo solo cuando sea verdad.
- **No alcance:** runbooks de producción/despliegue (S4/J4.7), troubleshooting de proveedores,
  documentación de endpoints (A1.8/OpenAPI).
- **Dependencia tipada:** `código` J1.1 (compose), `código` A1.7 (comandos de Alembic),
  `código` J1.4 (comandos de lint/tests si cambian). Si A1.7 no existe, documentar el comando
  como pendiente y no inventar rutas.
- **Entregables:** `docs/RUNBOOK-dev.md`; sección «Desarrollo local» en `README.md` con enlace;
  transcripción redactada de un checkout limpio.
- **Criterios de aceptación:**
  - [ ] Un clon limpio sigue el runbook de principio a fin sin pasos manuales no documentados.
  - [ ] Los comandos de levantar, testear, lintar y migrar están probados y fechados.
  - [ ] El `README.md` enlaza el runbook y su sección de estado no afirma nada no verificado.
  - [ ] Ningún comando imprime secretos y el runbook no contiene valores reales.
- **Pruebas/evidencia:** «Verificación obligatoria» de S1.md: transcribir la ejecución desde un
  entorno limpio (comando, fecha, entorno, resultado), redactada.
- **Archivos previstos:** `docs/RUNBOOK-dev.md`, `README.md`.

## 2. Diseño de la entrega

### 2.1 Contenido de `docs/RUNBOOK-dev.md`

1. **Requisitos:** Docker Engine + Compose v2, `uv`, Node LTS, `openssl`; versiones fijadas
   por L1.1 están en [../../VERSIONES.md](../../VERSIONES.md) (Python 3.12.14, Node 22.20.0).
2. **Preparar entorno:**
   ```bash
   git clone <repo> && cd Maulwurf
   cp .env.example .env
   # generar secretos locales sin imprimirlos en el historial de shell
   openssl rand -hex 32   # MAULWURF_SECRET_KEY
   openssl rand -hex 32   # MAULWURF_ENCRYPTION_KEY
   openssl rand -hex 32   # MAULWURF_OAUTH_STATE_SECRET
   ```
3. **Levantar todo:**
   ```bash
   cd infra && docker compose up -d --build --wait && docker compose ps
   ```
4. **TLS local:** la CA de Caddy vive en `caddy_data`; confiar en ella o usar `curl -k`;
   explicar el aviso del navegador y cómo confiar la CA (comando/UI), sin bajar la guardia TLS
   en producción.
5. **Migraciones (cuando A1.7 exista):**
   ```bash
   docker compose exec api alembic upgrade head
   docker compose exec api alembic current
   ```
6. **Healthchecks:**
   ```bash
   curl -kI https://localhost/
   curl -k https://localhost/me        # 401 sin sesión
   docker compose logs -f api
   ```
7. **Tests y lint:**
   ```bash
   cd apps/api   && uv sync --extra dev && uv run pytest -m "not integration and not provider and not load"
   cd apps/ingest && uv sync --extra dev && uv run pytest -m "not integration and not provider and not load"
   cd apps/api   && uv run ruff check . && uv run mypy .
   cd apps/web   && npm ci && npm run lint && npm run typecheck && npm run test && npm run build
   ```
8. **Integración local (servicios reales):** levantar `postgres`/`redis` y ejecutar
   `pytest -m integration` con `MAULWURF_DATABASE_URL`/`MAULWURF_REDIS_URL` al compose.
9. **Apagar / limpiar:** `docker compose down` (conserva `pgdata`) y `down -v` (destructivo,
   aviso explícito); recordar que **no hay audio persistido que borrar**.
10. **Solución de problemas:** puertos 80/443 ocupados, secretos con `change-me` (fail-fast de
    `app/core/config.py`), CA no confiada, primer build lento.
11. **Enlaces:** ADRs, `ESPECIFICACION.md`, `PLAN_SPRINTS.md`, catálogo de tests, bitácoras.
