## 1. Scope

| In D2.7 | Not in D2.7 |
|---|---|
| Clickable citations to `/biblioteca/{audio_id}?segment={segment_id}` | Backend citation contract changes |
| Reader segment highlight/focus when the link opens | Citation labels rebuilt in the browser |
| Sanitized Markdown for assistant messages | Markdown parsed for user messages |
| No arbitrary links or images from model output | External links rendered as navigable sources |
| Accessible citation list and keyboard focus | Audio playback or download |
| Manual browser evidence for E-S2-JL-09 | New Playwright/E2E harness |

The existing `citation` event already carries the server-derived `label` and `url`; the
frontend only validates and renders them.

## 2. Fixed decisions

1. **Library, not a custom parser.** Add `react-markdown`, `remark-gfm` and
   `rehype-sanitize`; update `package.json` and `package-lock.json` together (ADR-0003).
2. **No raw HTML.** Do not add `rehype-raw`; `rehype-sanitize` and explicit components
   keep transcript/model text inert.
3. **Only citations are links.** Markdown `a` elements render as text; `img` elements do
   not render. The citation registry is the only navigation source.
4. **Server label is authoritative.** The UI prints `citation.label` unchanged, including
   `segment N` when no reliable time exists. It never formats or invents `mm:ss`.
5. **Fail closed on URLs.** Only `/biblioteca/{uuid}` and
   `/biblioteca/{uuid}?segment={uuid}` are accepted. Other paths, hosts, protocols, extra
   query parameters or malformed identifiers render as plain text.
6. **Same-tab SPA navigation.** Use React Router `Link`; the reader already scrolls,
   focuses and marks the requested segment with `aria-current="location"`.

## 3. Code

- `apps/web/src/lib/markdown.ts`
  - `safeCitationHref(url)`: canonicalizes a validated reader URL or returns `null`.
- `apps/web/src/components/chat/Citation.tsx`
  - `CitationLink`: `[n] label` as a `Link` or plain text when the URL is rejected.
  - `CitationList`: accessible list, preserving the existing citation de-duplication.
- `apps/web/src/components/chat/MarkdownBody.tsx`
  - `ReactMarkdown` with `remarkGfm`, `rehypeSanitize` and explicit element components.
  - Links become text, images are omitted, tables scroll horizontally, code uses the
    existing mono font and palette.
- `apps/web/src/components/chat/ChatWorkspace.tsx`
  - User messages stay literal text.
  - Assistant messages render `MarkdownBody`.
  - Citation items render `CitationList`.
  - Stream parsing, cancellation and history recovery remain unchanged.

## 4. Security and editing behavior

- `react-markdown` outputs React elements; no `dangerouslySetInnerHTML`.
- HTML tags in model or transcript text are inert.
- Markdown links are not navigable, even when their protocol looks safe.
- Images are not fetched; only their alternative text, if any, may be shown as text.
- Citation URLs are revalidated in the browser even though the backend generated them,
  because persisted history is still untrusted input.

## 5. Tests - C-S2-DA-05 and E-S2-JL-09

## 7. Risks

| Risk | Mitigation |
|---|---|
| Arbitrary model links | `a` rendered as text; `img` omitted; sanitizer and tests |
| Persisted malformed citation URL | Strict `safeCitationHref` allowlist; fail closed |
| Markdown split across stream deltas | ReactMarkdown tolerates incomplete syntax; test live and EOF |
| New runtime dependency | Lockfile in the same change; `npm ci` in verification |
| Server label uses date, not class title | Render the authoritative label; changing it is a backend/L2.6 ticket |
| No browser E2E harness | Manual evidence for E-S2-JL-09; Playwright remains out of scope |
| Initial bundle grows with Markdown deps | Build passes at 551.71 kB with Vite's >500 kB advisory; code splitting is a later optimization, not a D2.7 blocker |
