## 1. Scope

| In D2.3 | Not in D2.3 |
|---|---|
| SSE via `EventSource` with a fresh DB `snapshot` on connect/reconnect | Library listing, retry and reupload (D2.4) |
| Polling fallback over `GET /audios/{id}` (manual and after bounded SSE failures) | `TranscriptReader` (D2.5) / chat (D2.6) |
| Real received bytes and completed/total fragments | Percentages, ETA or interpolated progress |
| `done` / `error` terminal handling; cleanup pending is never success | Cancelling ingestion when the view closes |
| Reusable `IngestProgress`; shown after an admitted upload | Backend changes to A2.9 |

Closing the SSE connection or polling view never cancels ingestion: the backend keeps working
and a later view reconnects to a fresh snapshot.

## 2. Fixed decisions

1. **State, not increments.** `snapshot` replaces the previous state. On reconnect the new
   snapshot wins; counters are never added to stale values.
2. **Measured values only.** The UI renders `received_bytes` and `fragments_done/total`.
   There is no percentage or ETA, including when `fragments_total` is unknown (`2/?` is not
   displayed; only `?/total` when only the numerator is missing).
3. **No unbounded reconnect loop.** `EventSource` reconnects natively; after
   `max_sse_failures = 2` consecutive failures the client closes it and switches to polling.
   Polling uses backoff + jitter, `Retry-After` through `apiFetch`, and stops after
   `max_poll_failures = 5` with an explicit retry control.
4. **One transport at a time.** Starting polling closes SSE and cancels timers; only one
   fetch is in flight. Unmount aborts it.
5. **Terminal is honest.** `done` only accepts `ready|partial`; `failed` always arrives as
   `error`. After a terminal the source closes and late frames are ignored. The attempt
   status is not re-rendered after `done` because the `progress` frame does not repeat it.
6. **Cleanup pending is work, not success.** `transcript_committed_cleanup_pending` shows an
   explicit warning while the aggregate is still `processing`.

## 3. API contract used

- `GET /audios/{id}/progress` (`text/event-stream`, `Cache-Control: no-store`):
  - `event: snapshot` → `{attempt: {status, received_bytes, fragments_done, fragments_total},
    stages: {index, analyze}, aggregate}`.
  - `event: progress` → `{received_bytes, fragments_done, fragments_total}`.
  - `event: done` → `{aggregate: "ready"|"partial", stages}`.
  - `event: error` → `{code, detail?}`; `failed` uses the attempt `error_code` or
    `aggregate_failed`.
  - `: ping` heartbeats; the stream is capped server-side and a reconnect receives state.
- `GET /audios/{id}` as polling fallback: `attempt`, `stages` and `aggregate_status`
  (equivalent snapshot; `attempt` may be `null`).

## 4. Code, step by step

### Step 1 — Pure model (`apps/web/src/lib/progress.ts`)

`ProgressSnapshot`, `ProgressAttempt`, `ProgressStages`, `ProgressEvent`,
`parseProgressEvent`, `snapshotFromDetail`, `reduceProgress`, `fragmentLabel`,
`isCleanupPending`, `progressAggregate`. Malformed payloads return `null`; nothing is
inferred from a missing field.

### Step 2 — Transport (`apps/web/src/lib/sse.ts`)

`createProgressSource(audioId, handlers, options)` with an injectable `EventSource` factory,
snapshot fetcher, timers and random source for deterministic tests. It owns SSE listeners,
the failure counters, the single polling loop, abort/close and terminal shutdown.

### Step 3 — Component (`apps/web/src/components/IngestProgress.tsx`)

Reusable panel with aggregate/attempt/stage badges, real bytes, fragments, cleanup-pending
warning, transport indicator, manual polling button, bounded retry and a terminal error view.
It uses the existing `StatusBadge` and `formatBytes` helpers.

### Step 4 — Integration (`components/upload/UploadForm.tsx`)

After an admitted `202`, mount `IngestProgress` with the reservation `audio_id`. For
`200 duplicate_exact` use the canonical `audioId`. No bytes are retained by the component.

## 6. Risks and open points

| Risk | Mitigation |
|---|---|
| A2.9 is still `in progress` | Consume only the frozen contract; no backend edits; confirm with the area-A owner before the PR |
| EventSource retries forever on 401/404 | Bounded failures switch to polling, which also has a bounded failure budget and manual retry |
| `progress` does not repeat attempt status | Terminal `done` hides the stale attempt badge; the aggregate is the final truth |
| Duplicate SSE + polling | A single mode guard and source close before polling |
| Cleanup pending looks like success | Explicit warning while aggregate is `processing`; never rendered as ready |
| Full live evidence needs admitted audio | The real sink (A2.13/S2.1) is still open; record the blocked browser check and do not claim live E2E from unit tests |
