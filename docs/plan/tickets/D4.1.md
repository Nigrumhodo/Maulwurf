## 2. Contract notes

- `GET /me/notifications` returns the complete preference set; `PATCH /me/notifications`
  applies only the sent fields and answers the complete set with `Cache-Control: no-store`.
- `digest_weekday` is **0 = Sunday** (frozen by `apps/api/app/services/digests.py`);
  `digest_daily_time` is `HH:MM` in the profile's local timezone, minute precision only.
- `reminder_offsets_hours` accepts 1-8784 hours and `reminder_allday_offsets_days`
  1-366 days, at most ten each; the server normalizes them descending and unique. An empty
  list is valid and means no reminders of that type. Explicit `null` is rejected.
- `POST /notifications/test` answers `202` with a `delivery_uncertain` warning or `409`
  `notifications_test_unavailable` with `gmail_not_opted_in`/`recipient_unverified`. J4.1
  owns the real send; the test records an audited occurrence only.
- `GET /me` does not expose `email_verified`, so the screen cannot pre-disable the test
  button for an unverified recipient; it surfaces the closed `409` reason instead.

## 3. Behavior

- `SettingsPage` renders a "notificaciones" card after "perfil" and before the Google
  Calendar panel. It loads the preferences once, shows a retry on failure, and never
  guesses defaults if the read fails.
- The Gmail block states what is sent (T-48/T-24/T-2 timed and T-3d/T-1d all-day
  reminders at 09:00 local, daily and weekly digests), the recipient (`user.email`), how
  to turn it off, and that the server controls delivery. A preference alone sends nothing.
- Daily and weekly digests have independent switches; the weekly selector labels
  `0..6` as domingo..sábado. The time input is the profile's local wall clock.
- The two threshold lists are editable with add/remove, bounded to the API limits and
  normalized before saving. Invalid input is rejected client-side before any request.
- Saving sends only changed fields, applies the server response, and reports field
  messages from `422`. The test button is disabled until the opt-in is saved and while
  there are unsaved changes; a `202` shows the API warning and a `409` shows the closed
  reason.
- No email, Calendar event or outbox row is created by D4.1. The test occurrence stays
  `pending` with `attempts=0` and `sent_at=NULL` until J4.1 consumes it.
