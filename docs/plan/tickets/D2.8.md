# D2.8 - Browser privacy (S2 scope): implementation plan

- Ticket: D2.8 (S2, P0) - Owner: ARES313 - Claimed: 2026-11-02 (UTC) - Status: done
- Contract: `docs/ESPECIFICACION.md` M1/M9 - `docs/plan/S2.md` section D2.8
- Tests: C-S2-DA-07 (`docs/PLAN_TESTS.md`)
- Depends on: D2.1-D2.7; the API `NoStoreMiddleware` from A4.6 is already present
- Scope decision: enforce no-store on private API responses and browser data; the SPA shell
  remains cacheable because it contains no private data.

## 1. Scope

| In D2.8 | Not in D2.8 |
|---|---|
| Force `cache: "no-store"` on private API requests | `no-store` on the SPA HTML shell |
| Verify the API's structural no-store middleware | New backend cache middleware |
| Release the SRT object URL on every path | Audio playback or preview |
| Regression tests for upload file release | Deleting the user's local original file |
| Audit IndexedDB, Cache Storage and service workers | New browser storage features |
| Global no-audio-player/no-audio-download sweep | Removing TXT/SRT transcript exports |

## 2. Current audit

Already correct:

- `apps/api/app/core/cache_control.py` applies `Cache-Control: no-store` to every HTTP
  response, including redirects, errors and SSE; `test_cache_control.py` and
  `test_hardening.py` cover it.
- `bootstrapCsrf()` already requests `/me` with `cache: "no-store"`.
- No service worker, `Cache Storage` or `IndexedDB` exists in the web app.
- The only persisted keys are non-private: `maulwurf-theme` in `localStorage` and
  `maulwurf-guest` in `sessionStorage`.
- There is no `<audio>`, `<video>`, `new Audio()` or `new Video()`.
- The only exports are transcript TXT and SRT; no audio download exists.
- Upload forms release the selected `File` on cancel, success and reset.

Gaps:

- `apiFetch()` does not force `no-store`; `fetchSubjects()` and `fetchCapabilities()` do
  not pass it explicitly.
- `triggerDownload()` revokes the SRT object URL but not through a `finally`, so a thrown
  `click()` could retain it.
- A caller could currently override the cache mode.
- The privacy sweep and browser evidence are not recorded.

## 3. Code decisions

1. **`apiFetch` is private-only.** Always send `cache: "no-store"` after spreading the
   caller options, overriding any caller value. A future public/cacheable endpoint must
   use a different client.
2. **No new storage.** Keep `maulwurf-theme` and `maulwurf-guest`; they contain no private
   class data. CSRF remains in memory only.
3. **No audio path.** No player, preview, object URL or download for audio. TXT and SRT are
   text exports required by D2.5.
4. **Release object URLs in `finally`.** The SRT blob URL is revoked even if the click
   fails.
5. **Release `File` in the existing flows.** Cancel, success and reset clear the file and
   progress; the original local file is never deleted by the app.
6. **The SPA shell may be cached.** The private data is in API responses; the shell contains
   no class text.

## 4. Code

- `apps/web/src/lib/api.ts`: force `cache: "no-store"` in `apiFetch` and document the
  private-only contract.
- `apps/web/src/lib/reader.ts`: make `triggerDownload` release the object URL in `finally`.
- No production changes to upload flows unless the new regression tests expose a leak.
- No API, Caddy or migration changes.

## 5. Tests - C-S2-DA-07

- `tests/unit/upload-form.test.tsx`: cancel and success clear the selected file/progress and

- Browser sweep: API responses carry `Cache-Control: no-store`; `caches.keys()` and

  no audio/video element or audio download exists.

## 7. Risks

| Risk | Mitigation |
|---|---|
| A future public endpoint needs caching | Keep `apiFetch` private-only; introduce an explicit public client |
| `EventSource` cannot set a fetch cache mode | Rely on the API's structural `no-store` header |
| SPA shell remains cacheable | Accepted: it contains no private data |
| Object URL leak on download error | Revoke in `finally`; regression test |
| Static source scan gives false positives | Use the manual C-S2-DA-07 checklist plus behavioral unit tests |
