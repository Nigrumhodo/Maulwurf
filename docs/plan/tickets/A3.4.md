## 2. Contract

`POST /tasks/{id}/confirm` returns `202` with the updated task and the promoted
`revision_id`.

- Stale task version -> `409 version_conflict`.
- Pending revision with no `revision_id` -> `409 revision_required`.
- Foreign, activated or stale revision -> `409 revision_stale`/`version_conflict`.
- Unresolved date -> `422 date_unresolved`.
- Missing/invalid Calendar block -> `422 event_block_missing`/`event_block_invalid`.
- Extraction or corpus-grounded chat without a reconstructible source ->
  `422 evidence_invalid`.
- Without a ready Google integration -> `status=confirmed`, `calendar_sync_status=blocked`,
  no outbox, no error.
- With a ready integration -> `calendar_sync_status=pending`, `tasks.calendar_id` from
  `settings`, and one `sync_task_event` outbox for the new version.

The effective fields come from the active row plus the selected revision's
`proposed_fields`. The revision is activated only in the transaction that bumps
`tasks.version`, updates `due_version` when the due representation changed, and enqueues
the outbox.

## 3. Supporting fixes

- `calendar_resume` now writes `tasks.calendar_id` from
  `settings.calendar_write_calendar_id` when moving `blocked -> pending`.
- A successful first connect also resumes blocked tasks, not only a reconnect.
- `TaskSnapshot.has_event_block()` checks the real `event_*` pair, so an all-day deadline
  with a timed agenda block is not blocked.
- `GET /integrations/status` adds `calendar_write_ready`, computed from connection,
  Calendar scopes and the write calendar.
