## 2. Backend PATCH

`PATCH /tasks/{id}` is implemented as the A3.3 write slice:

- `version` is mandatory; stale values return `409 version_conflict` with the current
  version and status.
- Active `needs_review`/`pending` tasks update in place, increment `version` and, when the
  due representation changes, increment `due_version`.
- `confirmed` tasks do not mutate active columns. The endpoint creates a
  `task_revisions` row with `revision_type=edit_of_confirmed`, `base_task_version` and
  `proposed_fields`, and returns the active task plus `revision_id`.
- Due fields enforce the A3.1 contract: `resolved` has exactly one of `due_date`/`due_at`,
  `all_day` matches the representation, and unresolved states carry neither.
- `event_block` is replaced as a whole when supplied and is independent from the due pair:
  - all-day uses `start_date`/`end_date_exclusive`;
  - timed uses `start_at`/`end_at`;
  - mixed, incomplete or inverted pairs return `422`.
- `pending_revision.proposed_fields` is now part of `TaskOut`.
- Tenant ownership and `Cache-Control: no-store` are preserved.
