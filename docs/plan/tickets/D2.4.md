## 1. Scope

| In D2.4 | Not in D2.4 |
|---|---|
| Real tenant listing grouped per subject | `TranscriptReader` and `?segment=` (D2.5) |
| Aggregate + attempt + per-stage states, including `partial` | Clickable citations (D2.7) |
| Permanent "audio not kept" notice | Chat UI (D2.6) |
| "Upload again" only without usable text | New backend endpoints or retry semantics |
| "Retry analysis/index" only over failed/cancelled stages | Reupload variant confirmation (use D2.1 flow) |
| Reuse of D2.2 streaming upload and D2.3 honest progress | Real Riva/LLM calls |

The library never infers a transcript from an aggregate that does not guarantee it. `ready`
and `partial` mean usable text; `processing` and `failed` do not.

## 2. Fixed decisions

1. **Grouping preserves server order.** `groupBySubject` keeps the backend order and the order
   inside each subject. S2 has no cursor, so the page requests the maximum `limit=100` and
   shows an explicit truncation note when that limit is reached.
2. **Actions are disjoint.** `failed` (no usable text) only offers **upload again**.
   `partial` (usable text) only offers retry over the stages in `failed|cancelled`.
   `ready` offers the reader placeholder, disabled until D2.5.
3. **Retry reads fresh state.** Before `POST /audios/{id}/retry` the page fetches
   `GET /audios/{id}` and uses its `transcript.version` and current stage states. A stale list
   can therefore produce an honest refresh/notice instead of a wrong body.
4. **Reupload reuses D2.2.** `POST /audios/{id}/reupload` opens a new ephemeral attempt; the
   response `upload_url` feeds the same streaming component/helpers as D2.1/D2.2. Cancelling
   aborts the `PUT` and calls the cancellation endpoint.
5. **One expanded progress panel.** D2.3's `IngestProgress` is mounted only for the selected
   row, not for every class, to avoid parallel SSE connections.
6. **No reader fiction.** The reader button is disabled and labelled as D2.5 work because the
   structured segments/summary contract still does not exist (A2.9 gap).

## 3. API contract used

- `GET /audios?limit=100[&subject_id=]` → `{items: [AudioListItem]}` with `subject`,
  `class_date`, `attempt`, `stages` and `aggregate_status`; `Cache-Control: no-store`.
  Unknown/foreign `subject_id` returns an empty list.
- `GET /audios/{id}` → list fields + `transcript {version, timestamp_precision, char_count}`
  + `exports {txt, srt}`; `404` for foreign/tombstoned.
- `POST /audios/{id}/retry` body `{stages: ["index"|"analyze"], transcript_version}` →
  `202 {audio_id, transcript_version, runs}`; `409 transcript_unavailable|invalid_transition`.
- `POST /audios/{id}/reupload` → `201 {audio_id, attempt_id, upload_url,
  upload_expires_at, outcome: "reupload"}`; only without usable text and no active attempt.
- `PUT {upload_url}` → `202 accepted` or `200 duplicate_exact`; same D2.2 error mapping.

## 4. Code, step by step

### Step 1 — `apps/web/src/lib/library.ts`

Types for list/detail/retry, `fetchAudios`, `fetchAudioDetail`, `retryAudio`, `reuploadAudio`,
`groupBySubject`, `hasUsableTranscript`, `failedStages`, `isCleanupPending`, `audioLabel`,
`stageLabel` and `libraryActionError` (`transcript_unavailable`, `invalid_transition`,
`not_found`, 429/503).

### Step 2 — Shared upload panel

Extract the D2.2 file/progress/cancel UI into
`apps/web/src/components/upload/AudioUploadPanel.tsx` and the shared file validation into
`pickUploadFile` (`lib/upload.ts`). `UploadForm` keeps its reservation/variant orchestration;
the library uses the same panel for reupload. No upload rules are duplicated.

### Step 3 — `apps/web/src/components/library/AudioCard.tsx`

Renders title/date/language/timezone, aggregate, attempt and stage badges; explicit cleanup
warning; explicit `partial` failed-stage text; upload-again vs retry vs disabled reader; and the
selected row's `IngestProgress`.

### Step 4 — `apps/web/src/pages/BibliotecaPage.tsx`

Loads list + capabilities in parallel (capabilities failure does not block listing), groups by
subject, keeps a single expanded progress row, and owns retry/reupload/cancel/upload/notices.
Upload again opens a reservation and reuses `AudioUploadPanel`; retry fetches fresh detail and
requires `transcript.version`.

## 6. Risks and open points

| Risk | Mitigation |
|---|---|
| A2.9 is still `in progress` | Consume only its frozen responses; no backend edits; coordinate before PR |
| List has no cursor | Request the maximum and show an honest truncation note |
| Retry list is stale | Re-read detail before sending `stages` + `transcript_version` |
| Reupload variant conflict | Clear the absorbed reservation and send the user to the D2.1 confirmation flow |
| Full browser E2E needs admitted audio | A2.13/S2.1 still gate real ingestion; record the blocked E2E and do not mark D2.4 done from unit tests only |
| Reader depends on D2.5 | Keep the button disabled with an explicit explanation |
