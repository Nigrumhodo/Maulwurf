## 1. Scope

| In D2.2 | Not in D2.2 |
|---|---|
| `PUT` to the reservation's relative `upload_url` with a streaming body | SSE/polling of ingestion progress (D2.3) |
| Real byte progress counted from the file as it is sent | Library listing / reupload (D2.4) |
| Cancel aborts the `PUT` + calls the cancel API + releases the `File` | Transcript reader (D2.5) |
| `200 duplicate_exact`, `202` admitted, `409 duplicate_variant` confirm round trip | Real Riva/NVIDIA calls (F0 gates open) |
| Typed error mapping (`409/410/413/415/422/503`) | Real ingest sink reaching the service (S2.1/C2) |

The binary is sent from the browser to the same-origin relative URL; it is never persisted in
the browser (no IndexedDB/Cache Storage, no object URL/player, no Server Actions).

## 2. Fixed decisions

1. **Relative URL only.** `uploadContent` rejects anything that is not a leading `/` path, so the
   `PUT` always travels through Caddy to the reservation endpoint.
2. **No retry of a consumed stream.** `apiFetch` treats `PUT` as non-idempotent; the upload sets
   `retries: 0`. On a retryable error the user sends again from the `File` (slice-based reads are
   re-readable), never from a partially consumed stream.
3. **Progress is bytes, not fiction.** `createProgressStream` reads 64 KiB slices and reports
   `{sentBytes, totalBytes}`; there is no invented percentage of transcription (that is D2.3).
   Slicing is used instead of `file.stream()` because jsdom lacks it and it keeps memory bounded.
4. **Cancel is two actions.** Abort the in-flight `PUT` (the server also cancels on disconnect via
   `_abort_disconnected`) **and** call `POST /audios/{id}/attempts/{attempt_id}/cancel`; `409
   invalid_transition`/`404` mean the attempt is already final and are swallowed.
5. **Variant confirmation is human.** `409 duplicate_variant` opens `ConfirmDialog`; confirming
   repeats `POST /audios` with `variant_confirmation_token` and re-sends the same `File`.
   `200 duplicate_exact` is a success (existing class), not an error.

## 3. API contract used

- Reservation (`201 AudioCreated`): `{audio_id, attempt_id, upload_url, upload_expires_at}`;
  `upload_url` = `/audios/{id}/content?attempt_id={aid}`.
- `PUT /audios/{id}/content?attempt_id=…` (relative, `X-CSRF-Token` injected by `apiFetch`):
  - `202 {attempt_id, status, received_bytes}` — admitted by the ingest sink.
  - `200 {audio_id, outcome: "duplicate_exact"}` — canonical class already exists.
  - `409 duplicate_variant {existing_audio_id, variant_confirmation_token, expires_at}`.
  - `409 attempt_not_active`, `410 upload_expired`, `413 payload_too_large{max_bytes}`,
    `415 unsupported_format`, `422 variant_hash_mismatch`, `503 capacity_unavailable`.
- `POST /audios/{id}/attempts/{attempt_id}/cancel` → `202 {attempt_id, status}`;
  `409 invalid_transition` after commit/final.

## 4. Code, step by step

### Step 1 — Pure helpers (`apps/web/src/lib/upload.ts`)

`formatBytes`, `acceptedFileExtensions`, `validateFile` (empty/size/format), `createProgressStream`,
`uploadContent` (relative `PUT`, `duplex:"half"`, `retries: 0`), `cancelAttempt`,
`variantConflict`, `mapUploadError`, `releaseUploadResources`; `buildAudioCreate` accepts the
optional `variant_confirmation_token`.

### Step 2 — `apps/web/src/components/upload/UploadForm.tsx`

Phases `form → ready → uploading → done`. After the reservation: simple file input (`accept` from
capabilities, client-side size/format check), byte progress bar labelled as sent bytes, cancel
button, `ConfirmDialog` for variants, and a result view for admitted/duplicate. Cancel and unmount
abort the controller and drop the `File`. Typed errors that invalidate the reservation return to
the form; retryable ones stay on the reservation.

### Step 3 — Cleanup

Remove the unused validation helper and its test (no production import remained).

## 7. Risks and open points

| Risk | Mitigation |
|---|---|
| Default sink answers `503` before reading a byte | Surface the typed retry message; no fake success; E2E waits for S2.1/C2 |
| `duplex` not typed in lib.dom | Narrow intersection cast; Chromium requires it for a streaming body |
| Abort race with cancel API | Abort first, then cancel; `409`/`404` are treated as already final |
| Variant token leaks to logs | Token lives in component state only; never logged, never persisted |
| Large `File` in memory | 64 KiB slice reads; the `File` reference is dropped on finish/cancel |
