## 2. Fixed decisions (do not reopen in the code PR)

1. `api` terminates the public `PUT`; `ingest` is reached only on the internal network.
2. Two phases: `receive` (stream, hash, probe, hold) and then `admit` or `discard`.
3. Credential `v1.<kid>.<payload>.<mac>`, HMAC-SHA256 with a domain prefix, canonical JSON,
   per operation, bound to attempt, audio, user, fencing token and (phase 2) instance;
   `exp = now + CREDENTIAL_TTL`. Secret of at least 32 bytes in every environment.
4. After the acquire only `ingest` writes ingestion status, `error_code` and cleanup.
5. `api`'s SHA-256 is the dedupe hash; `ingest`'s must match it.
6. No new capacity limits. Durations are the named settings of ADR-0008 §0
   (`CREDENTIAL_TTL`, `HOP_IDLE_TIMEOUT`, `HOLD_TIMEOUT` = 30 s, `HOP_CONNECT_TIMEOUT` = 2 s),
   each its own constant; the queue holds one chunk. The 32-byte secret minimum is a
   security floor, not a capacity limit.
7. `api` sends its own SHA-256 and byte count in the `admit` body; `ingest` fails closed.

### Step 2 — Credential (`apps/api/app/services/ingest_credential.py`)

```python
Op = Literal["receive", "admit", "discard"]

@dataclass(frozen=True)
class CredentialClaims:
    op: Op
    attempt_id: uuid.UUID
    audio_id: uuid.UUID
    user_id: uuid.UUID
    fencing_token: int
    instance: str | None  # None for receive; the receive answer's instance for admit/discard
    expires_at: int  # Unix seconds

def mint(claims: CredentialClaims, *, kid: str, secret: bytes) -> str: ...
def verify(token: str, *, keys: Mapping[str, bytes], expected_op: Op, now: int,
           instance: str | None) -> CredentialClaims: ...  # raises CredentialError
```

- Token `v1.<kid>.<payload_b64>.<mac_b64>`. Payload keys exactly `op, att, aud, uid, ft,
  ins, exp`; `json.dumps(..., sort_keys=True, separators=(",", ":"), ensure_ascii=True)`;
  base64url without padding; MAC over `b"maulwurf-ingest/v1." + kid + b"." + payload_b64`;
  compare with `hmac.compare_digest`. `verify` re-serializes the decoded payload and rejects
  it unless the bytes are identical, then checks `op == expected_op`, `exp`, and `ins`.
- `verify` lives here too, so tests prove the round trip, and S2.11 copies the same function
  into `apps/ingest/maulwurf_ingest/credential.py`. The two packages stay independent
  and never import each other.
- Add `tests/unit/test_ingest_credential.py` with **fixed test vectors** (secret, claims,
  expected token) in `tests/fixtures/ingest_credential_vectors.json`. S2.11 must run the same
  vectors against its copy. Cases: round trip; wrong secret; unknown `kid`; previous `kid`
  accepted only when configured; altered payload; altered MAC; expired; `admit` token used
  as `discard` (and every other op swap); wrong `ins`; unknown `op`; missing field; extra
  field; non-canonical JSON with the same keys is rejected.

### Step 3 — Protocol change (`apps/api/app/services/uploads.py`)

Change `ReceptionSink` to:

```python
@dataclass(frozen=True)
class Received:
    sha256: str
    received_bytes: int

class ReceptionSink(Protocol):
    async def begin(self, *, user_id, audio_id, attempt_id, fencing_token: int,
                    declared_bytes: int | None) -> None: ...
    async def write(self, chunk: bytes) -> None: ...
    async def finish(self) -> Received: ...
    async def abort(self) -> None: ...          # cancel the in-flight stream, no answer expected
    async def discard(self, reason: DiscardReason) -> None: ...  # raises SinkError unless verified
    async def admit(self) -> Admission: ...
```

`DiscardReason` is a `Literal` with exactly the reasons of ADR-0008 §3. Then in
`receive_content`:

1. Read `attempt.fencing_token` before `begin` and pass it.
2. Hot cut at the limit and every `SinkError` during the stream: call `abort()` (not
   `discard`), then raise as today.
3. Disconnect (`_abort_disconnected`): call `abort()`; if `finish()` already returned, call
   `discard("client_disconnected")`. **Remove** `attempt.status = "cancelled"` and its commit.
4. After `finish()`: compare `received.sha256` with the local hash and
   `received.received_bytes` with the local count. On mismatch: `discard(
   "reception_integrity_failed")` (lenient) and `ApiError(500, "internal_error", …)`.
5. Variant hash mismatch: `discard("variant_hash_mismatch")` (verified). **Remove** the
   `attempt.status = "rejected"` / `error_code` writes.
6. `_resolve_duplicate`: `discard("duplicate_exact")` / `discard("duplicate_variant")`.
7. DB failure after receive and failed `admit()`: `discard("api_error")` (lenient).
8. Empty body (`received == 0`): keep `415`; call `abort()` before `finish()`.
9. `UnavailableReceptionSink` implements the new methods with the same `503`.
10. Update the doubles in `tests/integration/test_put_content_dedupe.py` and
    `tests/unit/test_upload_stream.py` to the new protocol and assert the **reason** passed to
    `discard` for each existing case instead of the status the API used to write.

### Step 4 — Client (`apps/api/app/services/ingest_sink.py`)

`IngestReceptionSink(base_url, secret, client: httpx.AsyncClient)`:

- `begin`: mint `op=receive` with `ft=fencing_token`; create `asyncio.Queue(maxsize=1)`;
  start a task `client.put(url, content=self._body(), headers=…)` where `_body` is an async
  generator that yields queue items until a sentinel. Headers: `Authorization`,
  `Content-Type: application/octet-stream`, `X-Maulwurf-Declared-Bytes` when known. Do not
  set `Content-Length`.
- `write`: if the task already finished, map its answer now (an early `413/415/503/409` from
  ingest must stop the browser stream); otherwise `await queue.put(chunk)`.
- `finish`: put the sentinel, await the task, map the answer (§5 of this plan); on `200`
  store `fencing_token` from the body and return `Received`.
- `abort`: cancel the task and close the stream; never raises.
- `admit`/`discard`: mint with the stored token and instance; `POST`; map. `admit` sends
  `{"sha256", "received_bytes"}` (the API's own values). `discard` raises `SinkError`
  unless the body says `"cleanup_status": "verified"`.
- Cancellation: every await on the internal request sits in `try/finally` that cancels the
  request task and closes the stream, so an `asyncio.CancelledError` from the browser side
  closes the TCP connection to `ingest` immediately.
- Timeouts: `httpx.Timeout(connect=HOP_CONNECT_TIMEOUT, read=HOP_IDLE_TIMEOUT,
  write=HOP_IDLE_TIMEOUT, pool=HOP_IDLE_TIMEOUT)`, module constants. One shared
  `AsyncClient` created in the FastAPI lifespan of `app/main.py` and closed on shutdown.
- `get_reception_sink()` returns `IngestReceptionSink` when both settings are set, else the
  unavailable sink. It must never log the credential, headers or body.

### Step 5 — Answer mapping (inside `ingest_sink.py`)

Map internal answers to `SinkError(code)` exactly as ADR-0008 §8, then extend
`_sink_api_error` so that `attempt_not_active` → `409`, `payload_too_large` → `413` with
`max_bytes`, `unsupported_format` → `415`, `capacity_unavailable` → `503` + `Retry-After`,
everything else → `500`. Transport errors (`httpx.ConnectError`, `httpx.TimeoutException`,
`httpx.RemoteProtocolError`) → `capacity_unavailable`. `401` → `internal_error` and one
`logger.error("ingest.credential_rejected attempt_id=%s")`.

### Step 7 — Fake ingest for tests (`apps/api/tests/fakes/ingest_app.py`)

A small Starlette/FastAPI app that implements ADR-0008 §3 in memory **without storing the
body**: it hashes and counts the stream, verifies the credential with the Step 2 function,
keeps per-attempt state (`receiving` / held / admitted / discarded) and can be told to fail
(`413` at N bytes, `415`, `503`, `409`, drop the connection mid-stream, return a wrong hash,
`discard` → `failed`, never answer). Run it with uvicorn on a free loopback port inside the
test (fixture), not through `httpx.ASGITransport`, so real chunked streaming and TCP
backpressure are exercised.

## 4. What S2.11 must build (interface handed over)

So that S2.11 can start in parallel against the frozen contract:

1. `maulwurf_ingest/credential.py`: copy of `verify`, passing the shared vectors.
2. `maulwurf_ingest/receptions.py`: the three routes of ADR-0008 §3 under
   `/internal/v1/receptions/{attempt_id}`, mounted in `main.py`.
3. Instance id: random at startup, returned by `receive`, checked against `ins` in phase 2
   (`409 wrong_instance`).
4. `lease.acquire_bound(pool, *, user_id, audio_id, attempt_id, expected_token, instance,
   ttl)`: one `UPDATE … WHERE id AND user_id AND audio_id AND fencing_token = expected AND
   status = 'awaiting_upload' AND (lease_expires_at IS NULL OR lease_expires_at <= now())`
   that also sets `status = 'receiving'`, returning the new token.
5. `supervisor`: split `run_attempt` into `receive_and_hold` (lease keeper running) and
   `admit` (ASR + commit + cleanup), plus `discard(reason)` and the hold timeout. Cleanup
   stays in `finally` of whichever stage ends the attempt.
6. Slot gate: an in-process semaphore sized from the published `active_slots` (1 while D4
   is blocked), released on every terminal path.
7. `admit` verifies the API's hash and count from its body and fails closed.
8. `/readyz` gains a `credential` check (secret present).
9. Tests I-S2-SG-14 plus the contract cases above run against the real ingest instead of the
   fake (S2.11 owns that run).

## 6. Risks and open points

| Risk | Mitigation |
|---|---|
| The fake ingest drifts from the real one | Shared credential vectors; S2.11 reruns the contract cases against the real service |
| httpx streaming request bodies buffer more than one chunk | Case 13 measures it; if it fails, switch the body to a raw `httpx` stream with an explicit `aiter` and record the result |
| `absorb_reservation` deletes the attempt while ingest writes cleanup | ADR-0008 §5 orders `discard` (verified) before absorption; case 2 asserts the order |
| `api` is not hardened like `ingest` | No byte touches `api` disk (case 14). Hardening `api` is out of scope; recorded for J4.x |
| One `ingest` replica only | ADR-0008 §11; replicas stay unsupported until J4.x |
