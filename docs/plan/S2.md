## 0. Objective and exit gate

**Objective:** a complete vertical slice — upload audio → transcribe → verified cleanup →
hybrid index → chat with citations — working end to end with evidence.

**Exit gate — the sprint does NOT close without all of this:**

1. Real E2E browser → proxy → services with a 1 h synthetic class generated in RAM and
   the effective limit published in `/ingestion/capabilities`.
2. Audio absent (disk, Redis, logs, traces, caches) **before** indexing: indexing
   only sees text.
3. Chat answers with valid citations and persistent history (conversations/messages,
   idempotent `client_message_id`, streaming cancellation).
4. G1, G2-T **or** G2-X, G3, G4, and G5-F1 approved with evidence: non-persistence,
   isolation, transcript/index/chat retrieval, and per-language metric.
5. G4 publishes per language the numerator/denominator, dataset partition, and formula: Recall@8
   ≥ 0.85 (answerable), citation precision ≥ 0.95, abstention ≥ 0.90; retrieval
   p95 ≤ 500 ms and first token p95 ≤ 5 s.
6. **D3-Text closed** for the embedding/LLM provider and model before indexing or
   sending the first non-synthetic transcript; `P-S2-JL-10` records the real contract and
   S2's E2E/datasets use synthetic or redacted text.

Hard rule: if D3-Text remains `pending|blocked`, S2 may develop and measure with synthetic
text, but must not process real class transcripts.

**Interfaces frozen on Monday:** final shape of chunks/embeddings and `index(audio_id)`;
chat SSE `snapshot|delta|citation|done|error` with monotonic IDs and a single terminal event;
citation format `[Subject · Class · mm:ss]`; paginated `/search` contract.

## 1. Frozen contracts (exact reference)

### 1.1 Chunking and embeddings (provider: RAG · consumer: Infra)

- Target chunk **~800 tokens** with **~100** overlap, cuts at sentence/segment boundaries;
  Unicode offsets `[start, end)` preserved (emoji, accents, CJK count as 1); the
  `chunk_segments` table links chunk ↔ segments with a character range.
- Embedding versioning: each `index_version` records model, dimension, and version;
  a new generation is built in full and **activated atomically**; model/dimension/version are never mixed
  in the same active index.
- `index(audio_id)` event: idempotent job, consumes the frozen outbox shape (`type:
  index_requested`, IDs only); double delivery → a single index; no partially active
  versions.

### 1.2 Chat SSE events (provider: RAG · consumers: Web, API)

```text
event: snapshot → {"message_id", "status":"streaming"}
event: delta    → {"text": "…"}
event: citation → {"index": 1, "audio_id", "transcript_version", "chunk_id",
                   "segment_id", "t_start", "t_end", "label", "url"}
event: done     → {"message_id", "conversation_id", "status", "sources"}
event: error    → {"code", "message"}   # e.g. insufficient_evidence
```

All with a monotonic `id:`; after `snapshot` there are zero or more `delta|citation` and exactly
one `done|error`. `: ping` heartbeats between deltas; `Last-Event-ID` resumes omitting what was
already sent (the full state lives in the persisted message). Citations only reference
**IDs validated in the DB**; their markers stay buffered until validated. Without reliable offsets the label is "segment N", never an invented
minute. `message_sources` persists **all** the sources delivered to the model. Without sufficient
evidence there is abstention. The POST is consumed with `fetch`; on reconnect the persisted message is queried
and a repeated `client_message_id` never re-executes the model.

### 1.3 `/search` contract (provider: RAG+API · consumer: Web/Ctrl+K)

`GET /search?q=&subject_id=&from=&to=&limit=&cursor=` → `{"results": [{"chunk_id", "audio_id",
"subject", "class_date", "snippet", "segment_id", "t_start", "t_end", "score_rrf"}],
"took_ms"}`. Both branches (per-language FTS + pgvector) filter `user_id`, active
resources, active version, and filters **first** — never global top-k and filter afterwards. Without reliable
offsets, `t_start/t_end` null. Measured p95 target ≤ 500 ms.

## 2. RAG tickets (`L2.x`)

### L2.1 — Chunking with Unicode offsets

**Depends on:** L1.4 (contract), A2.1 tables · **Tests:** U-S2-JL-01.

How it must work: segmenter that takes transcript+segments and produces chunks per
§1.1; preferred cuts at sentence and ASR segment boundaries; each chunk stores
`audio_id`, `transcript_version`, character offsets over the full text, and its rows
in `chunk_segments`. Mandatory test cases: emoji, accents, CJK, exact cuts at
sentence boundaries, short final chunk.

### L2.2 — Versioned embeddings + HNSW

**Depends on:** A2.1 · **Tests:** U-S2-JL-02, P-S2-JL-10.

How it must work: batch embedding of chunks with the registered dimension/model;
cosine HNSW index; new index generation (`index_version`) built in full and
activated with a single atomic transaction/UPDATE — there are never moments mixing
active versions. `P-S2-JL-10` validates the provider's real contract (dimensions, quotas,
limits) and feeds decision D5. Before indexing real class text, D3-Text must
be closed for that model/provider (see §0.6); with the decision open only
synthetic or redacted text is indexed.

### L2.3 — Hybrid search with filters in both branches

**Depends on:** A2.1 · **Tests:** U-S2-JL-03/04.

How it must work: lexical `tsvector` branch with per-language configuration
(spanish/english/simple); cosine pgvector vector branch with `iterative_scan`/over-fetch and
recall measured with filters active (§2.5 of DISENO); deterministic RRF fusion (same
input → same output, documented `k`) with a total order and tie-break by `chunk_id` (stable
cursor); dedupe and diversity before top-k. `user_id`/version/tombstone filters applied **in both branches before top-k** (G3). Cases: redacted
corpus, excluded tombstone, excluded old version.

### L2.4 — `SearchService` + `GET /search`

**Depends on:** L2.3 · **Tests:** I-S2-JL-06 (in pair with A2.11).

How it must work: reusable service (consumed by chat and the endpoint); §1.3 params;
snippet with match context; segment timestamp when reliable. Integration
against real Postgres+pgvector with a test corpus.

### L2.5 — Chat SSE pipeline

**Depends on:** L2.4 · **Tests:** I-S2-JL-07/08.

How it must work, in order: (1) question embedding; (2) ~30 candidates per branch;
(3) RRF; (4) dedupe + diversity; (5) ~8 final chunks under token budget
(window − output reserve − margin; deterministically trimmed history, §2.7 of DISENO); (6)
prompt with context; (7) streaming to the client with §1.2 events and a citation buffer until
IDs are validated; (8) persistence in `messages` + `message_sources` (with A2.12). Mid-stream
cancellation cleans up state and leaves the partial `cancelled`.

### L2.6 — Validated citations

**Depends on:** L2.5 · **Tests:** U-S2-JL-05.

How it must work: each LLM citation marker is validated against the DB (the chunk/segment
exists, belongs to the tenant, active version) before emitting `citation`; without reliable offsets →
"segment N"; the model never generates the source. Zero unauthorized or invented IDs.

### L2.7 — G4 evaluation

**Depends on:** L2.1–L2.6 · **Tests:** G4 (weekly reproducible script).

How it must work: run the S1 dataset (≥50 questions/language, 15 non-answerable);
publish per language: Recall@8 with tenant/active-version filters on answerables,
citation precision ≥ 0.95, abstention ≥ 0.90
on non-answerables, with numerator/denominator. Never fudge metrics; if real classes are missing,
annotated synthetic class transcripts (text only).

### L2.8 — Latency measurement

**Depends on:** L2.4 · **Tests:** G4.

Retrieval p95 ≤ 500 ms on the reference corpus; chat first token p95 ≤ 5 s
(§8 requirement of the spec). Measured, not guaranteed; published with date and environment.

## 3. API/DB tickets (`A2.x`)

### A2.1 — Complete S2 data migration

**Depends on:** A1.5 · **Tests:** I-S2-AN-05, I-S2-AN-11.

Delivers an ordered, tenant-aware migration that starts from the S1 shape of `audios`,
`ingestion_attempts`, and `outbox_events` created in A1.5 and completes it, plus
`variant_confirmation_tokens`, `transcripts`, `segments`, `chunks`, `chunk_segments`,
`embeddings`, `index_generations`, `processing_runs`, `conversations`,
`messages`, and `message_sources`. `audios` has no `storage_key`; attempts record
versioned consent, lease/fencing, cleanup, and the
`transcript_committed_cleanup_pending` status; every tenant reference uses a composite FK. It includes
candidate GIN/HNSW indexes and the two partial indexes only where the design defines them.

**Mandatory verification:** migrate an empty DB and a previous version in compose; inspect
constraints/FKs and run the dedupe/chat suites. An emergency migration during the week is not acceptable.

### A2.2 — `GET /ingestion/capabilities`

**Depends on:** S1.A8 · **Tests:** U-S2-SG-01.

How it must work: exposes the limits **measured in the spike** (maximum payload, duration,
accepted formats, allowlisted languages, attempt TTLs) — not hard constants; it is updated
from the config published by the spike. The UI (D2.1) consumes this for the form.

### A2.3 — Real `POST /audios`

**Depends on:** A2.1, L1.6 · **Tests:** U-S2-AN-01.

How it must work: validates tenant subject, date, IANA zone, mandatory allowlist language,
`privacy_notice_version`, `cloud_processing_accepted=true`, and
`third_party_voice_acknowledged=true` before reserving. Creates `awaiting_upload` with lease and
relative URL. **Does not decide dedupe** because the hash does not exist yet: responds only `201`, `422`,
`429`, or `503`. After `duplicate_variant`, it accepts a valid opaque token in a second POST and
creates the reservation that will require a new upload.

### A2.4 — Binary `PUT` with streaming

**Depends on:** A2.3 · **Tests:** I-S2-AN-05.

How it must work: streaming reception without spool with session + CSRF + `attempt_id`; cuts
off when the limit is exceeded. Computes SHA-256 and cleans up before responding `200 duplicate_exact` or
`409 duplicate_variant`; it returns `202` only for new content admitted into the supervisor. The
409 includes a single-use/TTL opaque token; a second PUT verifies the hash before ASR. If the DB
fails after reception, it compensates the reservation/temporaries. Cases `410 upload_expired`, `409 attempt_not_active`,
and `422 variant_hash_mismatch` are covered.

### A2.5 — Dedupe by exact identity

**Depends on:** A2.3 · **Tests:** U-S2-AN-02, I-S2-AN-05.

How it must work: identity = SHA-256 + language + subject + date + zone. Decided in the
PUT after cleanup: exact returns the canonical class and releases the reservation; same hash with a different
context returns `409` with `existing_audio_id` and a `variant_confirmation_token` hashed in the DB,
single-use/TTL and bound to tenant/hash/metadata. The second POST consumes the token and the second
PUT verifies the hash again; mismatch → `rejected`, without ASR. A confirmed variant does not
mutate existing evidence/tasks. Two simultaneous uploads, an expired/reused token,
and different tenants are tested.

### A2.6 — State machine

**Depends on:** A2.1 · **Tests:** U-S2-AN-03.

How it must work: stages `not_requested|pending|running|succeeded|failed|cancelled`; ASR
includes `transcript_committed_cleanup_pending` between commit and `succeeded`. That status is not
exposed as success and blocks only index/analysis. Aggregate: `processing`, `ready`, `partial`,
`failed`; `not_requested` **≠** success. Expired upload, rejected format, silence, and technical
loss have typed destinations; every invalid transition returns `409`.

### A2.7 — Cancellation, tombstone, and fencing

**Depends on:** A2.6 · **Tests:** U-S2-AN-04, I-S2-AN-06.

How it must work: cancelling invalidates the fencing token → late commits rejected;
the supervisor cancels subprocess/gRPC and cleans up. `DELETE /audios/{id}` = tombstone: cancels
attempts/jobs, deletes transcript/chunks/embeddings/derived tasks/summary/citations; Google
events already created are kept by default (user is notified); deleting them requires an
explicit option via `google_remote_operations`. Deleting while ASR runs → clean cancellation without
orphans. Purge of derivatives verified by tests.

### A2.8 — `retry` vs `reupload`

**Depends on:** A2.6 · **Tests:** I-S2-AN-08.

How it must work: `POST /audios/{id}/retry` requires `{stages:["index"|"analyze"],
transcript_version}` and only creates idempotent runs over text. `reupload` only exists without
a usable transcript and creates a new ephemeral session with the same identity. The decision
matrix covers `409 transcript_unavailable|invalid_transition` and rejects empty,
duplicate, obsolete, or not-required stages.

### A2.9 — Reading, SSE, and exports

**Depends on:** A2.6 · **Tests:** I-S2-AN-07/09.

How it must work: `GET /audios?subject_id=` (tenant listing), `GET /audios/{id}`
(detail with per-stage statuses + aggregate + `attempt`), `GET /audios/{id}/progress` SSE with
**snapshot from the DB on connect/reconnect** (owner only), exports: `transcript.txt`
whenever there is a transcript; `transcript.srt` **only** with valid, ordered times
within the duration (otherwise: `409 srt_unavailable`). Progress with real bytes and
`done/total` fragments — zero invented percentages.

### A2.10 — Atomic commit + outbox gate

**Depends on:** S2.5 (contract) · **Tests:** I-S2-AN-10.

How it must work: one transaction creates `transcripts`, `segments`, and
`index/analyze(enabled=false, blocked_reason=cleanup_pending)` events; it persists language, model,
configuration, version, and precision. Then it moves to
`transcript_committed_cleanup_pending`; empty/silence → `rejected/no_usable_text`. Only the
reconciler with verified cleanup enables these events. Calendar/notifications/deletions
do not use this gate. Red/green test and post-commit recovery are mandatory.

### A2.11 — `GET /search`

**Depends on:** L2.3 · **Tests:** I-S2-JL-06 (in pair with L2.4).

How it must work: §1.3 endpoint with tenant/subject/date filters; snippet + audio +
valid timestamp; real `took_ms`. Shares the `SearchService` with chat (one
implementation, two consumers).

### A2.12 — Chat persistence (M7)

**Depends on:** A2.1, L2.5 (contract) · **Tests:** I-S2-AN-11.

How it must work:

1. Tables `conversations` (mode `all|subject|class` + `subject_id`/`audio_id` per mode,
   coherence CHECK), `messages` (role, content, status
   `streaming|completed|failed|cancelled`, `client_message_id` unique per conversation for
   idempotency), `message_sources` (all sources delivered to the model, with audio_id,
   segment_id, spans).
2. Endpoints: `POST /chat/conversations` (201/422 chat_mode_invalid),
   `GET /chat/conversations` (tenant listing), `GET /chat/conversations/{id}/messages`
   (paginated history), `POST /chat/conversations/{id}/messages` (SSE with fetch;
   repeated `client_message_id` → returns the original message without re-executing), `DELETE
   /chat/conversations/{id}` (204, tombstone and source purge), `POST
   /chat/conversations/{id}/messages/{message_id}/cancel` (202, partial `cancelled`).
3. Tenant isolation on all endpoints; deleting a conversation purges sources.

## 4. Ingestion/ASR tickets (`S2.x`)

### S2.1 — Real reception and validation

**Depends on:** A2.2/A2.3, S1.A8 · **Tests:** U-S2-SG-02.

How it must work: capabilities served with spike limits; streaming reception to
private `tmpfs` per attempt with incremental SHA-256; ffprobe validates container, codecs,
real duration, and channels (spike decision table; playlists/URLs/malformed
rejected); the real hash and duration are validated by ffprobe, not `Content-Length`.

### S2.2 — Bounded ffmpeg and fragmentation

**Depends on:** S2.1 · **Tests:** U-S2-SG-03.

How it must work: ffmpeg without network, argv built without shell interpolation, CPU/memory/output/time
limits; normalization to WAV PCM 16-bit mono at the validated sample rate;
fragmentation per the **real** spike limits (do not assume 10 min), cuts at
silences with tested overlap.

### S2.3 — Backpressure and boundary reconciliation

**Depends on:** S2.2 · **Tests:** U-S2-SG-04.

How it must work: sequential processing with backpressure (no decoding 3 h into RAM);
reconciliation between fragments: remove duplicated overlap words/text, global timestamps
= fragment offset + local time, stable order. Test cases: silences,
mid-word boundaries, full overlap.

### S2.4 — Isolated Riva client and classified retries

**Depends on:** S2.2 · **Tests:** U-S2-SG-05.

How it must work: blocking gRPC client isolated from the event loop (executor); deadlines and
cancellation tested; retries: transient gRPC retries (max 3, backoff+jitter within
the lease); invalid auth/language/format does **not** retry; exhausting the total deadline →
`requires_reupload`. `P-S2-SG-12` (protected) minimal regression against real Riva after
client changes.

### S2.5 — Atomic commit (ingestion side)

**Depends on:** S2.3/S2.4 · **Tests:** I-S2-SG-06.

How it must work: contract shared with A2.10 — single transcript+segments transaction
+ disabled outbox; persistence of language/model/version/`timestamp_precision`; empty or
silence = result without usable text without padding; low quality → structured warnings
(no PII).

### S2.6 — Cleanup in `finally` and gate

**Depends on:** S2.5 · **Tests:** I-S2-SG-07.

How it must work: when ASR ends (success **or** error): close buffers/files/clients,
delete original/converted/fragments; `cleanup_status` verified independently; attempt `succeeded` **only after commit and verified cleanup**; only then
enables the outbox. Red test if `succeeded` without cleanup.

### S2.7 — Post-commit reconciler and fencing

**Depends on:** S2.6 · **Tests:** I-S2-SG-08/09.

How it must work: process dead after the commit → the reconciler verifies cleanup and
enables the outbox **without retranscribing**; fencing token per attempt: an owner with an
expired lease does not publish the transcript; a stale token is rejected.

### S2.8 — Cancellation matrix

**Depends on:** A2.7 · **Tests:** I-S2-SG-10.

Exact cases: disconnection during reception → cancels+cleans; after 202 → continues under
lease; closing tab/SSE after 202 → **does not cancel**; cancel after commit → `409` with
current status, the transcript is not destroyed.

### S2.9 — E2E with a 1 h synthetic class

**Depends on:** S2.1–S2.8, D2.2/D2.3 · **Tests:** E-S2-SG-11.

How it must work: 1 h synthetic class generated in RAM with known text, transcribed
end to end via Caddy from the browser; evidence: correct transcript,
real `timestamp_precision`, published effective limit, zero audio persistence. Friday
demo.

## 5. Infra/Integrations tickets (`J2.x`)

### J2.1 — Real outbox dispatcher

**Depends on:** A2.10, U-S1-JF-04 · **Tests:** U-S2-JF-01.

How it must work: consumes `outbox_events` and publishes only non-sensitive IDs/config. Rejects
`index/analyze` blocked by `cleanup_pending`; Calendar, notifications, and deletions already
enabled are dispatched after revalidating authorization/tombstone/version. Backoff+jitter max 3
only for transients; non-transients do not retry.

### J2.2 — Idempotent `index(audio_id)` job

**Depends on:** J2.1 · **Tests:** I-S2-JF-02.

How it must work: encapsulates L2.2's logic (on day 4–5 it connects to the real one; before that a stub that
logs the call); verifies ownership/tombstone/version before publishing; double delivery
→ a single index; no partially active versions; retries backoff+jitter (max 3
transients).

### J2.3 — Reconstruction after losing Redis

**Depends on:** J2.1 · **Tests:** I-S2-JF-03.

How it must work: `FLUSHALL` in a test environment → jobs are regenerated from
DB/outbox and walk the full path to completion; audio is **not** reconstructed
(ever).

### J2.4 — Reconciler

**Depends on:** J2.2 · **Tests:** I-S2-JF-04.

How it must work: dead attempts marked; stuck outbox re-published; duplicate
executions resolved by uniqueness/lease. Fault injection with J2.7.

### J2.5 — Minimal observability

**Depends on:** J2.1 · **Tests:** C-S2-JF-10 (operational checklist).

JSON logs with `request_id/audio_id/attempt_id/run_id` without sensitive payloads; metrics:
RAM/tmpfs/slots, outbox lag, retries, age of temporaries; **immediate alert on failed
cleanup**; minimal per-stage failure panel.

**Mandatory verification:** inject failed cleanup in compose and attach a redacted capture
of the alert, metrics, and absence of sensitive payload to the C-S2-JF-10 evidence.

### J2.6 — Automated E2E smoke

**Depends on:** J2.2, S2.9, D2.2, D2.6 · **Tests:** E-S2-JF-06.

Smoke on every MR: upload → transcript → cleanup → index → question with citation, against
compose. Fixtures per the PLAN_TESTS §0.4 rules (synthetic audio in RAM).

### J2.7 — Coordinated fault injection

**Depends on:** S2.5, A2.10 · **Tests:** I-S2-JF-05.

Crash injected before and after the commit with the API/DB and Ingestion areas; result per contract:
pre-commit crash → nothing published, audio cleaned; post-commit crash → reconciler
enables the outbox without retranscribing. An expired lease does not mark verified cleanup. Evidence
documented in logbooks.

**Depends on:** L2.6, D2.5 · **Tests:** C-S2-DA-05.

### D2.8 — Browser privacy (scoped to S2)

**Depends on:** — · **Tests:** C-S2-DA-07.

## 7. Integrated flow of the week (vertical slice)

1. **Upload:** D2.1 form → `POST /audios` reserves (A2.3) → streaming `PUT`
   (D2.2/A2.4) → `202`, `200 duplicate_exact`, or `409 duplicate_variant`; the latter cleans up,
   delivers a token, and requires a second POST+PUT.
2. **Transcription:** S2 supervisor (S2.1–S2.4) → atomic commit (S2.5+A2.10) → verified
   cleanup (S2.6) → reconciler enables the outbox (S2.7).
3. **Indexing:** dispatcher (J2.1) → `index(audio_id)` (J2.2/L2.2) → active hybrid
   index.
4. **Query:** `/search` (L2.4+A2.11) and chat with citations (L2.5/L2.6 + A2.12) → UI D2.5–D2.7.
5. **Evidence:** 1 h class E2E (S2.9) + CI smoke (J2.6) + fault injection (J2.7).
